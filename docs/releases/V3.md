## Added since v1.0.0
- Listening (T14): player (recorded override > generated file > browser voice), one-play assessment, dictation, `content:audio`.
- Assessment (T16): "실전 세트" per scoring section from the ASSESS pool only. ASSESS records are kept out of every learning list (`AppModel.pool` excludes them) and a question/passage that was ever shown (learning, diagnostic, earlier assessment) is never offered.
- Readiness (plan.md §9): last 28 days, first exposure only, answer not seen first, listening needs a played non-browser audio file. n=0 none / n<20 자료 부족 / n≥20 관찰됨 / n≥30 + Wilson reference interval. 상대 취약 only when every section has n≥20 (accuracy <0.60 or ≥0.15 behind the best). No probability, no estimated official score, no 19-point verdict.
- Report: SVG charts (28-day study minutes, five mastery stages, per-section accuracy), listening TTS-source badge and source mix, excluded-attempt counts, user-declared official results (`OFFICIAL_RESULT_REPORTED`).

## Fixed on the way
- `deviceSeq` could be duplicated when events were recorded without awaiting (the quiz does that): sequence and timestamp are now taken synchronously and the meta write is serialised (`tests/storage/storage.test.ts`).
- A model rebuilt right after a quiz could miss the last answers: `refresh()` now waits for in-flight event writes.
- Listening revision by the verifier model could drop the audio key: the key is recomputed from the revised script (`mergeListeningRevision`).
