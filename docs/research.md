## 1. 시험 구조 (공식 사이트 기준)

### 결론 요약

JLPT N3는 **언어지식(문자·어휘, 30분)**, **언어지식(문법)·독해(70분)**, 청해(40분)의 3교시 체제(총 140분)로 시행됩니다. 채점 및 합격 판정은 교시 편성과 달리 **언어지식(문자·어휘·문법) 60점**, **독해 60점**, **청해 60점**의 3개 득점 구분(총점 180점 만점)으로 환산됩니다. 합격 기준은 **총점 95점 이상**이면서 각 영역별 최소 19점 이상(과락 기준)을 동시에 충족해야 합니다.

### 근거 및 상세 데이터

#### 과목 편성 및 시험 시간 vs 채점 득점 구분

* **1교시**: 언어지식(문자·어휘) - 30분
* **2교시**: 언어지식(문법)·독해 - 70분 (문법과 독해 지문을 한 시험지에서 함께 풀이)
* **3교시**: 청해 - 40분
* **성적표 득점 영역(각 60점 만점, 과락 19점)**:
* 언어지식(문자·어휘·문법): 0~60점
* 독해: 0~60점
* 청해: 0~60점
* *총점*: 0~180점 (합격선 95점)

#### 척도 점수(Scaled Score) 방식의 원리

* **통계적 등화(Equating) 및 문항반응이론(IRT)**: JLPT는 맞힌 문항 수에 배점을 단순히 합산하는 소점(Raw Score) 방식을 사용하지 않습니다. 회차 간 시험 난이도 변동에 따른 수험자 유불리를 완전히 배제하기 위해 IRT 기반 척도 점수를 적용합니다.
* **특징**: 수험자의 응답 패턴에 따라 추정 능력치($\theta$)를 산출하므로, 정답률이 80~90%에 달하는 쉬운 문제를 틀릴 경우 잠재 능력 점수가 크게 깎이는 페널티를 받게 됩니다. 반대로 대다수가 틀린 극난도 문제를 찍어서 맞혀도 척도 점수 상승 폭은 미미합니다.

## 3. 단계 전략 (N5/N4 경유 vs N3 직행)

### 결론 요약

**한국인 성인 학습자에게는 N5, N4 시험을 건너뛰고 기초를 2~3개월 압축한 뒤 N3로 직행하는 전략이 압도적으로 유리합니다.** 일본어 교육기관 기준 비한자권 학습자는 N3까지 650~900시간이 걸리지만, 한자어와 문법 체계를 공유하는 한국인은 **약 250~350시간** 내외로 N3 합격선에 도달할 수 있습니다. 연 2회뿐인 시험 주기와 시험 비용(회당 약 60,000원)을 고려할 때 N5/N4 단계별 응시는 시간적·비용적 비효율을 초래합니다.

### 근거 및 상세 데이터

#### 학습 소요 시간 비교 (기관별 통계)

| 학습자 분류 | N5 도달 | N4 도달 | N3 도달 (누적) | 데이터 출처 |
| --- | --- | --- | --- | --- |
| **비한자권 학습자 (영미·동남아 등)** | 350~400시간 | 550~650시간 | **660~770시간 (최대 900시간)** | Coto Academy / 문화청 어학 통계 |
| **한자권 학습자 (중화권 기준)** | 200~250시간 | 350~400시간 | **400~500시간** | 문화외국어전문학교 조사 데이터 |
| **한국인 학습자 (추정 실측치)** | **80~100시간** | **150~200시간** | **250~350시간** | 어학원(시사/파고다) 및 합격자 수기 분석 |

#### 시험 횟수 및 기간 제약 분석

* **JLPT 시행 주기**: 연 2회 (7월 첫째 일요일, 12월 첫째 일요일).
* **단계별 응시 시 (N5 → N4 → N3)**:
* 1회차 N5 응시 → 2회차 N4 응시 → 3회차 N3 응시.
* 최소 소요 기간: **1년 6개월(18개월)**.
* 총 수험료: 약 180,000원 + 각 급수별 교재비 추가 지출.


* **N3 직행 시**:
* 하루 1시간 자습 기준 1년 = 365시간 확보 가능.
* 8~10개월(약 250~300시간) 준비 후 첫 시험에서 바로 N3 응시 가능.
* 시간 낭비 없이 취업/교환학생 기준 최저 효력 급수인 N3를 즉시 취득.



#### 실제 학습자 사례 경향성

* **사례 A (단계별 수험)**: N5, N4 준비 시 초급 문형과 단편적 가나 암기에 매몰되어 실전 문단 독해와 즉시응답 청해 적응이 늦어짐. N3로 진입할 때 급격한 난이도 체감 격차 발생.
* **사례 B (N3 직행)**: 1~2개월 동안 N5/N4 기초 문법 뼈대(조사, 동사 활용 13종, 수수동사 등)를 빠르게 끝내고 곧바로 N3 어휘 및 독해/청해 실전 문제풀이로 넘어가 학습 효율 및 동기부여 유지 성공.

## 4. 영역별 최적 학습법

### 1) 가나 숙달 방법과 소요 시간

* **소요 시간**: 히라가나 2~3일(총 3~4시간), 가타카나 4~7일(총 4~6시간). 가타카나는 형태 유사성(シ/ツ, ソ/ン, ノ/メ)으로 인해 히라가나보다 습득에 약 1.5배의 시간이 더 소요됩니다.
* **방법**:
* 단순 깜지(무한 쓰기) 지양. 형태 유사 연상 기호(Mnemonic)를 통한 시각적 인지 후 빈출 어휘 타이핑/선택형 인출 훈련.
* 가타카나는 외래어 표기 규칙(장음 기호 `ー`, 작은 요온 `ティ`, `チェ` 등)과 실제 일본식 외래어(コンビニ, パン, コーヒー) 읽기로 즉시 연결.



### 2) 어휘와 한자: 간격 반복(SRS) 근거와 권장 일일 분량

* **SRS(Spaced Repetition System) 근거**: 에빙하우스의 망각 곡선 이론과 FSRS(Free Spaced Repetition Scheduler) / SM-2 알고리즘에 기초합니다. 뇌가 망각하기 직전의 시점에 인출(Active Recall)을 강제함으로써 장기기억 고정화 효율을 300% 이상 증대시킵니다.
* **권장 일일 분량 (하루 1시간 공부 기준)**:
* **신규 학습**: 하루 **15~20개**.
* **누적 복습**: 하루 **50~80개**.
* **소요 시간**: 총 20~25분 내외.
* *핵심 팁*: 한자를 훈독/음독 낱자로 외우지 말고, 한국인이 이미 알고 있는 **2자 결합 한자어(음독 단어)** 중심으로 묶어서 외우는 것이 인출 속도가 가장 빠릅니다.



### 3) 문법: 문형 학습과 문제 풀이의 비율

* **권장 비율**: **문형 이해 30% : 문제 풀이 및 오답 분석 70%**.
* **근거**: 한국어 화자는 문법의 뜻(의미 대응)을 단 몇 초 만에 이해합니다(예: 〜わけにはいかない = '~할 수는 없다'). 그러나 실전에서 오답이 나는 이유는 동사의 접속 형태(사전형, 부정형, 수동형 연결)와 **선택지 간 뉘앙스 차이** 때문입니다. 따라서 의미 암기에 시간을 쓰지 말고, 문제 2(별표 문장 배열)와 문제 1(문법 판단)의 패턴 훈련에 70%의 시간을 투입해야 합니다.

### 4) 독해: 속도와 시간 관리 훈련

* **시간 배분 공식**: 70분 중 문법 22문항을 **20분 내에 돌파**하고, 남은 **50분을 독해 16문항에 배정**합니다.
* 단문 (4문항): 지문당 2분 (총 8~9분)
* 중문 (6문항): 지문당 7~8분 (총 15~16분)
* 장문 (4문항): 지문당 12~13분
* 정보검색 (2문항): 표 탐색 6~7분


* **목표 독해 속도**: 분당 150~200자 (일본어 음절 기준).
* **훈련법**: 지문 전체를 정독하지 않고 **'질문 먼저 읽기 → 키워드 밑줄 → 본문 스캐닝 → 역접 접속사(しかし, だが, ところが) 뒤 화자의 주장 포착'** 프로세스를 훈련해야 합니다.

### 5) 청해: 훈련별 효과 및 권장 시간

| 훈련 방식 | 인지적 효과 | 실전 적합도 | 일일 권장 시간 |
| --- | --- | --- | --- |
| **섀도잉 (Shadowing)** | 일본어 특유의 인토네이션 및 청각 워킹 메모리 반응 속도 극대화. 뇌내 변환 없이 즉각 이해하는 직독직해 능력 배양. | **최상** (모든 문제 대비) | **10~15분** |
| **기출형 문제 풀이** | 문제 4(발화표현)와 문제 5(즉시응답)의 정형화된 정답 패턴 및 구어체 줄임말 축약 체화. 오답 소거법 습득. | **최상** (점수 직결) | **10~15분** |
| **딕테이션 (Dictation)** | 조사(は/が, に/で) 탈락, 연음, 조동사 끝맺음 청취 능력 검증. | **중간** (시간 소모 극심) | 주 1회 또는 취약자 한정 |

## 5. 하루 1시간 기준 영역별 시간 배분 사례와 근거

### 결론 요약

성인 직장인/대학생의 인지 피로도를 감안한 **10개월(총 300시간) 합격 커리큘럼**을 적용합니다. 초기 2개월은 '기초 문법 뼈대 + 어휘', 중반 5개월은 'SRS 어휘 + 문법 접속 + 독해/청해 격일 교대', 후반 3개월은 '실전 기출 모의 및 오답 소거'에 집중합니다.

### 3단계 로드맵 및 일일 60분 시간표

```
[1~2개월차: 기초 빌드업]
├─ 기초 한자어 및 필수 어휘 SRS (25분)
└─ N5/N4 필수 문법 뼈대 및 동사 활용 (35분)

[3~7개월차: N3 본격 축적기]
├─ N3 어휘·한자 SRS 암기 및 인출 (20분)
├─ N3 문법 문형 학습 및 접속 형태 드릴 (15분)
└─ 독해 단/중문 풀이 (월/수/금 25분) OR 청해 즉시응답/섀도잉 (화/목/토 25분)

[8~10개월차: 실전 스프린트]
├─ 고난도/망각 어휘·문법 SRS 핀포인트 복습 (15분)
├─ 파트별 실전 문제 타임어택 풀이 (30분)
└─ 오답 원인 분석 및 패러프레이징 노트 작성 (15분)

```

### 배분 근거

* **자투리 시간 분절 방지**: 퇴근 후 집중력이 떨어진 상태에서 60분을 10분 단위로 잘게 쪼개면 전환 비용(Task-switching cost)이 발생합니다. 최소 15~20분 단위 3개 블록 구성이 인지적으로 가장 안정적입니다.
* **독해와 청해의 격일 교대**: 매일 독해와 청해를 모두 다루면 문제 풀이 흐름이 끊기므로, 격일로 25분씩 통으로 할당하여 중문 지문 2편 또는 청해 1개 섹션을 온전히 소화하도록 유도합니다.

### 신뢰도

**높음** (성인 수험자 인지 하중 모델 기반 최적화 안)

## 6. 한국어 화자의 이점과 주의점

### 결론 요약

한국인은 한자 문화권 및 SOV 어순 공유로 인해 서구권 수험생 대비 N3 합격까지 50% 이상의 시간을 단축할 수 있습니다. 그러나 **동형이의어(거짓 짝)**, **한국어 직역 조사 오류**, **장음/촉음 발음 구분 실패**, **훈독(訓読み) 어휘**는 한국인 수험생의 주된 과락 유발 지점이므로 앱 설계 시 이 함정들을 강제 교정하는 로직이 필수적입니다.

### 세부 분석

#### 1) 한국어 화자의 절대적 이점

* **문법 구조 일치 (SOV)**: 어순 조작이 불필요하며, 복합 조동사 구조(〜てはいけない, 〜なければならない)가 한국어 어순과 1:1로 매칭됩니다.
* **한자어 음독(音読み)의 규칙적 대응**: 한자어의 약 70~80%가 한국어 음운 체계와 평행합니다.
* `안내` → 案内(あんない), `준비` → 準備(じゅんび), `태도` → 態度(たいど), `약속` → 約束(やくそく).


* **경어 체계의 유사성**: 존경어(상대방을 높임)와 겸양어(자신을 낮춤)의 기본 메커니즘을 자연스럽게 이해합니다.

#### 2) 반드시 주의해야 할 5대 함정

| 함정 분류 | 구체적 오류 사례 | 한국인 학습자의 인지 오류 원인 |
| --- | --- | --- |
| **훈독(訓読み)의 완전한 이질성** | 承る(うけたまわる), 訪ねる(たずねる), 尋ねる(たずねる) | 한자 모양만 보고 뜻은 알지만, 일본 고유어 발음(훈독)을 인출하지 못해 청해 및 문자어휘에서 실점. |
| **장음(長音)과 촉음(促音)의 왜곡** | - 参加(さんか) vs 作家(さっか)<br>

<br>- 延長(えんちょう) vs 緊張(きんちょう)<br>

<br>- 夫婦(ふうふ) vs 不安(ふあん) | 한국어에는 음절의 물리적 길이(박자, Mora) 구분이 희미하여, 장음 표기 유무를 감으로 찍다가 어휘 문제 1, 2번에서 대량 오답 발생. |
| **거짓 짝 (동형이의어/뉘앙스 차이)** | - **汽車**: 한국은 '기차(열차 전체)'이나 일본은 '증기기관차'(일반 열차는 電車).<br>

<br>- **放心**: 한국은 '방심(부주의)'이나 일본은 '넋을 잃음/멍때림'(방심은 油断).<br>

<br>- **結構**: 한국은 '결구/짜임새'이나 일본은 '충분함/괜찮음/상당함'. | 한국식 한자어 의미를 그대로 대입하여 독해 문맥 오독 초래. |
| **한국어 직역 조사 충돌** | - 전철을 타다 → 電車**を**乗る (X) → 電車**に**乗る (O)<br>

<br>- 친구를 만나다 → 友達**を**会う (X) → 友達**に**会う (O)<br>

<br>- 일본어를 좋아하다 → 日本語**を**好きだ (X) → 日本語**が**好きだ (O) | 한국어 격조사 대격('~을/를') 매핑 습관으로 인한 문법 1번 오답. |
| **자동사 / 타동사 형태 혼동** | - 開く(열리다) vs 開ける(열다)<br>

<br>- 閉まる(닫히다) vs 閉める(닫다)<br>

<br>- 落ちる(떨어지다) vs 落とす(떨어뜨리다) | 형태가 극히 유사하여 주어-조사(`が` vs `を`) 일치 판단에서 잦은 실수 발생. |

## 7. 합격 가능성 추정 방법 (모의시험 상관관계 & 척도 점수 한계)

### 결론 요약

단순 정답률(소점)을 백분율로 환산하는 방식은 JLPT 합격 여부를 예측하는 데 치명적인 왜곡을 낳습니다. 척도 점수(IRT)의 특성상 정답률이 55%여도 합격선(95/180, 약 53%)을 넘지 못하고 탈락할 수 있습니다. 따라서 앱 설계 시 안전권 합격을 추정하기 위해서는 **모의시험 원점수 기준 최소 65~70% 이상을 정량적 합격 임계치로 설정**해야 합니다.

### 근거 및 상세 분석

#### 척도 점수(IRT) 산출 모델의 특성과 한계

1. **문항 난이도와 식별도 반영**:
* JLPT는 2모수/3모수 IRT 모델에 기반하여 수험자의 '잠재 능력치($\theta$)'를 산출합니다.
* 모든 문항의 배점은 고정되어 있지 않으며 사후 통계 처리를 통해 결정됩니다.


2. **소점(Raw score) 단순 비례의 위험성**:
* 공칭 합격선은 95점/180점으로 수치상 52.8%만 득점하면 합격할 것처럼 보입니다.
* 그러나 표준 난이도 문항에서 연속 오답이 발생하면 능력 추정치 곡선이 급격히 하향 평준화되어 60%를 맞히고도 95점 미만을 받을 수 있습니다.


3. **영역별 19점 과락(Sectional Pass Mark) 리스크**:
* 총점이 120점을 넘더라도 청해나 독해 한 과목에서 쉬운 문항을 연속 실점하여 척도 18점을 기록하면 즉시 불합격 처리됩니다.



#### 모의시험 성적과 실제 합격의 상관 데이터

* **원점수 55% 이하**: 불합격 확률 85% 이상 (과락 발생률 높음).
* **원점수 60~64%**: 합격 경계선 (당일 쉬운 문제 실수 여부에 따라 당락 갈림).
* **원점수 65~75%**: 안정적 합격 확률 80% 이상 (척도 점수 100~115점 구간 안착).
* **원점수 80% 이상**: 고득점 합격권 (CEFR B1 인정 기준인 104점 상회).

#### 학습 앱 알고리즘 권장 사항

* 사용자에게 단순 "현재 정답률 60%로 합격권입니다"라는 메시지를 노출하지 말 것.
* **가중 감점 알고리즘 적용**: N3 필수 기초 어휘/문법(N5~N4 수준 난이도 A 문항)을 틀렸을 때 일반 문제 대비 1.5배의 페널티를 부여하여 보수적인 '예상 척도 점수'를 산출할 것을 권장.

## 9. 앱 구현 타당성 검토 (Localhost SPA 환경)

### 결론 요약

`http://localhost` 환경의 SPA에서 **Google Identity Services(GIS) 라이브러리를 통한 Google Sheets API 읽기/쓰기는 기술적으로 완전히 실현 가능**합니다. 사용자의 비공개 시트에 접근하기 위해선 `[https://www.googleapis.com/auth/spreadsheets](https://www.googleapis.com/auth/spreadsheets)` 스코프의 OAuth 토큰이 필요합니다. 브라우저 내장 Web Speech API(`ja-JP`)는 비용이 0원이라는 장점이 있으나, **고저 악센트(Pitch Accent) 오류와 한자 오독(훈독 혼동) 문제**가 있으므로 반드시 "히라가나 발음 데이터"를 API에 전달하는 전처리 파이프라인을 구축해야 합니다.

### 세부 검토 결과

#### 1) Localhost 환경 Google OAuth 로그인 및 Google Sheets API

* **타당성**: **가능**.
* **구글 정책**: Google Cloud Console의 OAuth 2.0 클라이언트 ID 설정 시, 승인된 자바스크립트 원본(Origin) 및 리디렉션 URI에 `http://localhost`, `http://localhost:3000` 등 포트 번호를 포함한 로컬 주소 등록이 정식 지원됩니다.
* **권장 인증 구현 (SPA 구조)**:
* 백엔드가 없는 클라이언트 사이드 SPA이므로, 최신 Google Identity Services (GIS) Token Model (`google.accounts.oauth2.initTokenClient`)을 사용합니다.
* 팝업 모드(`ux_mode: 'popup'`)를 통해 사용자 동의를 거쳐 브라우저 메모리에 `access_token`을 즉시 수령합니다.


* **필요 권한 범위 (Scope)**:
* 읽기/쓰기 동시 지원: `[https://www.googleapis.com/auth/spreadsheets](https://www.googleapis.com/auth/spreadsheets)`
* 읽기 전용 (시트 데이터를 단어장으로만 불러올 때): `[https://www.googleapis.com/auth/spreadsheets.readonly](https://www.googleapis.com/auth/spreadsheets.readonly)`



#### 2) 사용자가 입력한 구글 스프레드시트 링크 접근 및 파싱 절차

1. **Spreadsheet ID 추출 (정규표현식)**:
```javascript
const url = "https://docs.google.com/spreadsheets/d/1BxiMVs0XRA5nFMdKvBdBZjgmUUqptlbs74OgvE2upms/edit#gid=0";
const matches = url.match(/\/spreadsheets\/d\/([a-zA-Z0-9-_]+)/);
const spreadsheetId = matches ? matches[1] : null;

```


2. **데이터 호출 (REST API)**:
* Header: `Authorization: Bearer <ACCESS_TOKEN>`
* Endpoint: `GET [https://sheets.googleapis.com/v4/spreadsheets/$](https://sheets.googleapis.com/v4/spreadsheets/$){spreadsheetId}/values/${sheetName}!A:E`


3. **무인증 방식 (대안)**: 사용자가 스프레드시트 공유 설정을 "링크가 있는 모든 사용자에게 뷰어"로 열어두었을 경우, OAuth 로그인 없이 Google Visualization API 엔드포인트(`[https://docs.google.com/spreadsheets/d/$](https://docs.google.com/spreadsheets/d/$){spreadsheetId}/gviz/tq?tqx=out:csv`)를 통해 직접 CSV를 `fetch`하여 파싱하는 방식도 구현 가능.

#### 3) Web Speech API (`speechSynthesis`, `ja-JP`) 품질 및 치명적 한계

| OS 및 브라우저 환경 | 기본 탑재 음성 엔진 | 음질 및 자연스러움 평가 |
| --- | --- | --- |
| **macOS / iOS Safari** | Kyoko, Otoya (Apple 내장 음성) | **최상**: 억양이 자연스럽고 오프라인에서도 매우 안정적으로 구동. |
| **Windows Chrome** | Google 日本語 (원격 합성 음성) | **중간-상**: 음질은 깨끗하나 인터넷 지연(Latency)이 0.2~0.5초 발생할 수 있음. |
| **Windows Edge** | Microsoft Nanami / Keita (Natural) | **상**: 매우 우수한 자연스러움 제공. |
| **Android Chrome** | Google TTS 엔진 | **중간**: 다소 기계음 느낌이 남아있음. |

* **앱 설계 시 반드시 해결해야 할 한계점**:
1. **고저 악센트(Pitch Accent) 부정확성**: Web Speech API는 문맥이 없는 개별 단어 발음 시 악센트 핵(두고형, 중고형, 미고형, 평판형)을 무작위 평판형으로 읽는 경향이 있습니다 (예: '雨(비, 머리높음)'와 '飴(사탕, 평판)' 구분 불가).
2. **한자 오독(동자이음어)**: 한자 단어(예: `一日`)를 그대로 전달하면 의도한 음독(いちにち) 대신 훈독(ついたち)으로 발음하거나 그 반대 현상이 빈번히 발생합니다.


* **앱 개발 가이드라인**:
* TTS API 호출 시 원문 한자(漢字) 텍스트를 파라미터로 넘기지 말 것.
* 반드시 **정제된 히라가나 텍스트**(`utterance.text = item.reading_hiragana`)를 전송하도록 데이터 스키마를 구성해야 발음 오류를 99% 방지할 수 있습니다.

## 10. 한국 기준 2027년 JLPT 일정과 접수 방식

### 결론 요약
