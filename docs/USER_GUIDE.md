> **작성 기준:** `execution_plan.md` v3.4의 설계. 아직 구현 전이므로 **화면 이름·버튼 문구·명령 옵션이 실제와 다를 수 있다.** 구현이 끝나는 T09(v0.1.0 릴리스)에서 Claude Code가 실제 화면 기준으로 이 문서를 갱신하고, 이후 릴리스(v1.0.0, v2.0.0, v3.0.0)마다 다시 갱신한다.
> **표기:** ⚠ 표시는 외부 서비스 화면·정책이 바뀔 수 있어 실행 시점에 확인해야 하는 항목이다.

## 0. 한눈에 보기

### 0.1 구성 요소

| 구성 요소 | 위치 | 역할 | 누가 쓰나 |
|---|---|---|---|
| **학습 앱** | GitHub Pages의 `index.html` (모바일·PC 브라우저) | 매일 학습, 진단, 복습, 리포트 | 매일 |
| **내 구글 시트** | 내 구글 드라이브 | 학습 기록, 설정, 콘텐츠를 보관하는 저장소 | 앱이 자동 사용 |
| **콘텐츠 생성기(CLI)** | 내 PC의 `jlpt-app` 폴더 | 문제·단어·지문을 만들고 검증해 팩 파일로 묶음. Claude는 **API 방식** 또는 **headless 방식**으로 호출 | 2주마다 |
| **Claude Code** | 내 PC | 앱과 생성기를 개발·수정 | 개발할 때 |

### 0.2 무엇을 어디서 하나

| 작업 | 기기 | 빈도 |
|---|---|---|
| 학습(60분) | 모바일 또는 PC 브라우저 | 매일 |
| 동기화 상태 확인 | 앱 | 학습 후 |
| 런웨이(남은 학습 분량) 확인 | 앱 | 주 1회 |
| 콘텐츠 추가(생성 → 가져오기) | **PC** | 2주마다 |
| 백업 내보내기 | 앱 | 월 1회 |
| 앱 업데이트 배포 | PC | 개발 후 |

### 0.3 데이터 흐름

```text
[PC] 콘텐츠 생성기 ──(팩 파일 *.jlptpack.json)──> [앱: 가져오기] ──> [내 구글 시트]
                                                                       │
[모바일/PC 앱] <──── 콘텐츠·기록 읽기 / 학습 기록 쓰기 ────────────────┘
[PC] 앱에서 내보낸 progress.json ──> 생성기가 다음에 만들 분량을 계산
```

앱은 콘텐츠를 HTML에 담지 않는다. 콘텐츠와 학습 기록은 모두 **내 시트**에 있으므로, 앱 파일을 교체(버전 업)해도 데이터와 설정은 유지된다.

## 1. 최초 준비 (1회, 약 20~30분)

이 단계는 Claude Code가 대신할 수 없다. 일부가 빠져도 개발 초반(T00~T06)은 진행되지만, 구글 연동(T07)과 콘텐츠 대량 생성은 준비물이 있어야 한다.

### 1.1 계정

- **개인 Google 계정**을 사용한다. 회사 Google Workspace 계정은 관리자 정책으로 외부 앱 로그인이 막힐 수 있다.
- 이 앱은 **`spreadsheets` 권한(내 모든 구글 시트를 읽고 쓸 수 있는 넓은 권한)**을 요청한다. 앱은 입력한 시트 하나만 사용하도록 만들지만, 권한 자체는 넓으므로 **업무용 시트가 많은 계정은 피하는 것**이 안전하다.

### 1.2 Google Cloud 설정 ⚠

화면 이름은 Google이 바꿀 수 있다. 다르면 비슷한 항목을 찾는다.

1. Google Cloud Console(`console.cloud.google.com`)에서 **새 프로젝트**를 만든다(예: `jlpt-app`).
2. **API 및 서비스 > 라이브러리**에서 **Google Sheets API**를 찾아 **사용**으로 바꾼다.
3. **Google Auth Platform**(또는 OAuth 동의 화면)에서 앱 이름, 지원 이메일을 입력한다. 사용자 유형은 **외부(External)**, 게시 상태는 **테스트(Testing)**로 둔다.
4. **대상(Audience)**의 **테스트 사용자**에 **본인 계정**을 추가한다. (추가하지 않으면 로그인이 거부된다.)
5. **데이터 액세스(Data Access)**에서 범위(scope) `https://www.googleapis.com/auth/spreadsheets`를 추가한다.
6. **클라이언트(Clients)**에서 **OAuth 클라이언트 ID**를 만든다. 유형은 **웹 애플리케이션**이다.
   - **승인된 JavaScript 원본**에 아래 두 개를 입력한다. **경로 없이** 주소까지만 쓴다.
     - `https://<GitHub사용자명>.github.io`
     - `http://localhost:8080` (개발·검증용)
   - 리디렉션 URI는 입력하지 않는다.
7. 생성된 **클라이언트 ID**를 복사해 둔다. (클라이언트 **보안 비밀번호**는 이 앱에서 쓰지 않는다. 어디에도 붙여 넣지 않는다.)

> 처음 로그인하면 "Google에서 확인하지 않은 앱" 경고가 뜨는 것이 정상이다(테스트 상태의 민감 범위 앱). 본인이 만든 앱이므로 **고급 > 계속**으로 진행한다. 다른 사람에게 공개 배포하려면 별도의 Google 검증이 필요하다.

### 1.3 테스트용 구글 시트 2개

- 개인 계정 드라이브에 **빈 시트 1개**와 **샘플 데이터가 있는 시트 1개**를 만든다. 업무·실데이터 시트는 테스트에 쓰지 않는다.
- 두 시트의 주소창 URL(`https://docs.google.com/spreadsheets/d/.../edit`)을 메모해 둔다.

### 1.4 Claude 연동 (콘텐츠 생성용): API 방식과 headless 방식

콘텐츠 생성기는 Claude를 두 가지 방식으로 호출할 수 있다. **하나만 준비해도 되고, 둘 다 준비해 역할별로 섞어 써도 된다.** 방식 비교는 §5.5를 참고한다.

**A. API 방식**

1. Anthropic 콘솔에서 **API 키**를 만든다. ⚠ (Claude 구독과 별도로 과금되는 것이 일반적이므로 콘솔에서 확인한다.)

2. 콘솔의 **사용 한도(spend limit)**를 설정한다. 처음에는 월 소액으로 시작한다.

3. 한 번 실행할 때 쓸 **최대 비용**을 정해 `config.local.json`의 `maxUsdPerRun`에 적는다(§1.8). 단위는 달러다.

   ```text
   config.local.json
     maxUsdPerRun : 5
   ```

   - 처음에는 소액(예: `5`)으로 시작한다.
   - 생성기가 만들어진 뒤에는 `npm run content:fill -- --days 28 --dry-run`이 출력하는 **예상 비용**을 보고, 그 값의 1.2배 정도로 다시 정한다.
   - 이 금액 이하의 생성은 Claude Code가 묻지 않고 진행하고, 넘으면 멈추고 확인을 받는다.
   - 한 번만 바꾸고 싶으면 실행할 때 `--max-usd 3`처럼 옵션으로 덮어쓴다.

4. API 키는 PC의 `.env.local`에만 둔다. 앱·깃·휴대폰 어디에도 넣지 않는다.

**B. headless 방식 (Claude Code를 명령줄에서 비대화형으로 실행)**

1. **Claude Code를 설치하고 로그인**한다. 개발에 이미 쓰고 있다면 준비가 끝난 것이다.

2. 터미널에서 아래 명령으로 동작을 확인한다. JSON 응답이 오면 정상이다.

   ```text
   claude -p "ping" --output-format json
   ```

3. 한 번 실행할 때 쓸 **최대 호출 수**를 정해 `config.local.json`의 `maxCallsPerRun`에 적는다(§1.8). headless 방식은 달러 대신 호출 수로 관리한다.

   ```text
   config.local.json
     maxCallsPerRun : 100
   ```

   - **호출 1회**는 `claude -p`를 한 번 실행한 것(생성 요청 1건 또는 검증 요청 1건)이다. 문항 하나를 만들고 검증하려면 보통 여러 번 호출한다(대략 4~5회로 예상하며, 실제 값은 구현 후 `--dry-run`이 알려 준다).
   - 처음에는 작게(예: `50`) 시작해 파일럿으로 동작을 확인한다.
   - 생성기가 만들어진 뒤에는 `npm run content:fill -- --days 28 --dry-run`이 출력하는 **예상 호출 수**의 1.2배 정도로 다시 정한다.
   - 이 값은 **안전 상한**이다. 구독 사용량 한도를 호출 수로 정확히 환산할 수는 없으므로, 실제 한도에 먼저 걸리면 생성기가 멈추고, 같은 명령을 다시 실행하면 이어서 진행한다.
   - 한 번만 바꾸고 싶으면 실행할 때 `--max-calls 200`처럼 옵션으로 덮어쓴다.

4. ⚠ 구독 로그인으로 자동화 호출을 해도 되는지, 인증 요건이 무엇인지는 개발 초기(T00)에 공식 문서로 확인하고 `docs/decisions/llm-providers.md`에 기록된다. 일부 자료는 headless에도 API 키가 필요하다고 안내하므로, 안 되면 A 방식을 사용한다.
   - T00 확인 결과: 구독 로그인(API 키 없음)으로 `claude -p` 호출이 동작했다. 생성기는 `--safe-mode`를 붙여 호출하며(그렇지 않으면 개인 플러그인·설정이 매 호출에 실려 토큰이 크게 늘어난다), `--bare`는 구독 로그인을 읽지 못해 쓰지 않는다. 구독으로 자동화 호출을 해도 되는지 약관상 허용 범위는 확인하지 못했으므로 직접 확인한다.

**C. 점검**

두 방식 중 무엇이 쓸 수 있는 상태인지 한 번에 확인하려면 PC에서 실행한다.

```text
npm run content:doctor
```

API 키 존재와 1회 호출, `claude` 설치·로그인과 1회 호출, TTS 키를 점검하고 해결 방법을 알려 준다. 둘 다 안 되면 Claude Code가 직접 작성하는 폴백으로 진행하며, 대량 생성은 `BLOCKED(LLM)`이 된다.

### 1.5 청해 음원 (TTS) ⚠

- 기본은 **Google Cloud Text-to-Speech**다. 같은 Cloud 프로젝트에서 **Cloud Text-to-Speech API**를 사용 설정하고 **API 키**를 만든 뒤, 키의 사용 제한을 "Text-to-Speech API만"으로 좁힌다.
- 결제 계정 연결이 필요할 수 있고 무료 한도와 약관은 T00에서 확인한다. 다른 엔진으로 바꾸려면 개발 단계에서 `TtsProvider`를 교체한다.
- 청해는 v2.0.0부터 쓰므로, 이 항목은 v1.0.0 이후에 준비해도 된다.

### 1.6 GitHub 저장소와 Pages

1. GitHub에서 저장소 `jlpt-app`를 만든다. 무료 계정에서 Pages를 쓰려면 저장소를 **공개(Public)**로 해야 할 수 있다 ⚠(T00에서 확인). 공개되는 것은 앱 코드와 음원뿐이며, **학습 기록과 콘텐츠는 내 시트에 있으므로 공개되지 않는다.**
2. PC에서 `git push`가 되도록 인증을 준비한다(SSH 키 또는 `gh auth login`).
3. 첫 배포 후 저장소 **Settings > Pages**에서 소스를 **`gh-pages` 브랜치 / (root)**로 지정한다.
4. 앱 주소는 `https://<GitHub사용자명>.github.io/jlpt-app/` 형태다.

### 1.7 내 PC

- **Node.js LTS**, **git**, **Claude Code**를 설치한다. ⚠(Claude Code는 공식 설치 안내를 따른다.)
- 새 폴더 `jlpt-app/docs/`를 만들고 아래 문서를 넣는다.
  - `execution_plan.md`, `plan.md`, `research_revised.md`, `USER_GUIDE.md`

### 1.8 설정 파일 채우기

T01이 `config.local.example.json`과 `.env.local` 템플릿을 만들어 준다. **키 이름은 그 템플릿을 따른다.** 아래는 예시이며 값은 모두 본인 것으로 바꾼다.

```text
.env.local                (깃에 올라가지 않음)
  ANTHROPIC_API_KEY=...        (API 방식을 쓸 때만 필요)
  GOOGLE_TTS_API_KEY=...

config.local.json         (깃에 올라가지 않음)
  clientId        : 1.2에서 복사한 OAuth 클라이언트 ID
  pagesOrigin     : https://<GitHub사용자명>.github.io
  testSheetUrls   : 1.3의 시트 URL 2개
  maxUsdPerRun    : 1.4 A에서 정한 금액 (API 방식)
  maxCallsPerRun  : 1.4 B에서 정한 호출 수 (headless 방식)
  llm.generate    : { provider: "api" 또는 "headless", model: 생성 모델 }
  llm.verify      : { provider: "api" 또는 "headless", model: 검증 모델 }
                    (생성과 검증 모델은 서로 다르게. 연동 방식은 같아도 된다)
```

## 2. 개발 시작 (Claude Code)

1. 터미널에서 `jlpt-app` 폴더로 이동해 Claude Code를 실행한다.
2. `execution_plan.md` §13의 프롬프트를 그대로 붙여 넣는다.
3. 이후 Claude Code는 `docs/STATUS.md`에 진행 상황을 기록하며 T00부터 순서대로 진행한다.

### 2.1 사용자가 개입하는 경우

| 상황 | 의미 | 할 일 |
|---|---|---|
| `git push`, 페이지 게시, 저장소 공개 설정 확인 요청 | 외부에 반영되는 작업이라 승인이 필요하다. | 내용을 확인하고 승인한다. |
| 생성 비용이 `maxUsdPerRun`을 넘는다는 보고 | 비용 보호 장치다. | 금액을 확인하고 승인하거나 범위를 줄인다. |
| `BLOCKED(원인)` | 준비물이 없어서 못 하는 작업이다(예: 클라이언트 ID 없음). | 원인에 해당하는 준비물을 만들고 Claude Code에 "이어서 진행"이라고 말한다. |
| `FAIL` | 테스트가 3번 수정 후에도 실패한 작업이다. | 보고된 내용을 보고 지시하거나 건너뛰게 한다. |

### 2.2 세션이 끊겼을 때

새 세션에서 같은 프롬프트(§13)를 다시 붙여 넣으면 `STATUS.md`를 읽고 **마지막 완료 지점부터** 이어서 진행한다. 직접 `docs/STATUS.md`를 열어 현재 상태를 볼 수도 있다.

### 2.2.1 개발 명령 (PC, 저장소 루트)

| 명령 | 하는 일 |
|---|---|
| `npm install` | 의존성 설치(프로젝트 안 `.npm-cache` 사용) |
| `npm run build` | `dist/index.html` 한 파일 생성 |
| `npm run serve` | `http://localhost:8080`에서 `dist/`를 열어 확인(개발·검증 전용) |
| `npm run size` | 파일 크기·해시·외부 참조 점검 |
| `npm run check` | 타입 검사 + 테스트 + 빌드 |

### 2.3 버전별로 쓸 수 있는 기능

## 3. 앱 첫 실행

### 3.1 연결

1. 휴대폰 또는 PC의 **Chrome**으로 앱 주소(`https://<GitHub사용자명>.github.io/jlpt-app/`)를 연다.
2. 홈의 동기화 카드(또는 설정 > 시트 연결)에서 실행 환경을 확인한다. 파일을 직접 연 경우(`file://`)에는 **로컬 모드** 배지가 뜨고 "로컬 파일 모드에서는 Google 로그인을 지원하지 않습니다. Google Sheets 연결은 HTTPS 실행이 필요합니다."라는 안내만 나온다(§10 참고).
3. **설정 > 시트 연결**에서 **Google 계정으로 연결**을 누르고 개인 계정을 선택한 뒤 권한을 허용한다. (앱 빌드에 Client ID가 없으면 "Google Client ID가 이 빌드에 설정되어 있지 않습니다"라는 안내가 나오고 버튼이 없다. §1.8의 `clientId`를 채우고 `npm run build` 후 다시 배포한다.)
4. **시트 주소**를 붙여 넣고 **연결 확인**을 누른다. 처음에는 **테스트용 빈 시트**로 시작해 동작을 확인하는 것을 권장한다. 이 단계에서는 시트를 읽기만 한다.
5. "이 시트에 _JLPT_* 전용 탭을 생성합니다. 기존 탭은 수정하지 않습니다."라는 안내를 확인하고 **초기화 승인**을 누른다.
6. 앱이 `_JLPT_META`, `_JLPT_PACKS`, `_JLPT_CONTENT`, `_JLPT_SOURCES`, `_JLPT_EVENTS` 탭을 만들고 시드 콘텐츠를 등록한 뒤 바로 동기화한다. 이미 초기화된 시트에는 아무것도 덮어쓰지 않고 이어서 연결한다.
7. 연결을 풀고 싶으면 **연결 해제**를 누른다. 시트의 데이터와 이 기기의 기록은 삭제되지 않는다.
8. 토큰은 메모리에만 있으므로 새로고침하면 **다시 연결**이 필요하다(기록은 그대로다). 같은 계정·같은 시트로 다시 연결하면 이어서 동기화된다.

**새 기기**: 같은 구글 계정으로 연결하고 같은 시트 주소를 넣으면 앱이 이 시트의 프로필에 합류하고 설정·목표·진단 기록·콘텐츠를 복원한다. 이 기기에 이미 학습 기록이 있으면 섞지 않고 "다른 계정의 학습 기록이 연결되어 있습니다."라고 알린다.

### 3.2 목표 설정

- 설정 > **목표** 카드에서 **급수**(콘텐츠가 있는 급수만 선택 가능), **연도**, **회차(7월 / 12월)**를 고르고 **목표 변경**을 누른다. 시험일은 규정상 첫째 일요일로 계산한 **"예상일"**로 표시되며, **공식 공고 전에는 확정이 아니다.**
- 목표는 **설정 > 목표**에서 언제든 바꿀 수 있다. 바꿔도 지금까지의 풀이·설정·복습 기록은 지워지지 않고, 앞으로의 계획만 다시 계산된다.
- 공식 공고가 나오면 설정 > 목표의 **공식 시험일 입력 (공고 확인 후)**를 열어 날짜와 공고 주소(https)를 넣고 **공식 시험일 저장**을 누른다. 한국 JLPT 실시위원회 공지를 직접 확인한 날짜만 입력한다. 이미 지난 회차는 "선택 회차가 이미 지났습니다."로 거부된다.
- 홈의 목표 카드에는 `2027년 7월 (예상 7월 4일 / 공식 미확정)`처럼 표시되고, 남은 일수와 "최대 학습 가능 시간(하루 60분 기준 산술 상한)"이 함께 나온다.

### 3.3 배치 진단

- 홈의 **배치 진단 시작**(중간에 나갔다면 **진단 이어서 하기**)을 누르고 안내를 읽은 뒤 **진단 시작**(또는 **이어서 풀기**)을 누른다. 처음 보는 28문항(가나 8, 기초 8, 목표 등급 언어 6, 목표 등급 독해 6. 현재 목표 등급은 N3)을 푼다. 새로고침하거나 앱을 닫아도 푼 문항은 다시 나오지 않고 이어서 풀 수 있다. **시간 제한은 없고**, 중단했다가 이어서 풀 수 있다.
- 결과는 **시작 경로**(`가나·기초부터` / `기초 보강` / `목표 등급 중심`)를 정하는 용도다. JLPT 점수나 합격 가능성이 아니다.
- v0.1.0에서는 청해가 **"미측정"**으로 표시된다. 정상이다. 진단에 쓴 시간은 그날의 60분에서 차감된다.

## 4. 매일 학습 (60분)

### 4.1 홈 화면

| 항목 | 내용 |
|---|---|
| **오늘의 60분** | 영역별 배분 시간(분), 시작 버튼. **시작 전 안내**로 오늘 할 일, 진행 방식, 예상 소요를 보여 준다. |
| **오늘 복습** | 기한이 된 항목 수, 틀리기 쉬운 항목(약점) 수 |
| **영역 카드 3장** | 어휘·한자 / 문법 / 독해·청해. 숙련도 5단계 분포를 막대로 표시 |
| **목표** | 연도/월, 예상일, 남은 일수, 최대 학습 가능 시간 |
| **동기화 배지** | §4.5 참고 |

하단 탭은 **홈 / 학습 / 리포트 / 설정**이다.

### 4.2 문제 푸는 방법

1. 보기 4개 중 하나를 고른다. 시간 제한은 기본으로 없다.
2. **정답 확인**을 누른다.
3. 해설 화면에서도 **보기 4개가 그대로 보인다.** 오답 보기를 누르면 **왜 틀렸는지**와 **어떻게 고치면 맞는지**가 나온다.
4. 충분히 읽은 뒤 **다음 계속하기**를 눌러야 다음 문제로 간다. **자동으로 넘어가지 않는다.**
5. 문제나 해설이 이상하면 **문제 신고**를 누른다(§4.6).

### 4.3 숙련도 5단계와 복습

| 단계 | 이름 | 다음 복습 간격(정답일 때) |
|---|---|---|
| 0 | 새 항목 | 첫 정답 후 1일 뒤 |
| 1 | 학습 중 | 3일 뒤 |
| 2 | 익숙함 | 7일 뒤 |
| 3 | 거의 숙달 | 21일 뒤 |
| 4 | 숙달 | 21일 뒤 재확인 |

- 틀리면 한 단계 내려가고, 같은 세션에서 한 번 더 나오며, 다음 날로 예약된다.
- **복습 대상 = 기한이 된 항목 + 마지막 답이 오답인 항목** 하나의 규칙이다.
- 하루 예상 복습이 25분을 넘으면 그날은 **신규 항목이 0개**가 된다. 복습이 밀리지 않게 하려는 설계이며 오류가 아니다.

### 4.4 학습 탭 메뉴

| 메뉴 | 설명 | 버전 |
|---|---|---|
| 오늘 세션 | 오늘의 60분 순서대로 진행 | v0.1.0~ |
| 영역별 학습 | 어휘·한자, 문법, 독해, 청해를 직접 선택 | v1.0.0~ |

| 실전 세트 | 영역별 시험 시간을 선택해 푸는 세트 | v3.0.0~ |

### 4.5 동기화 상태 읽는 법

학습 기록은 먼저 **기기에 저장**된 뒤 **시트로 전송**된다. 전송은 20건, 약 60초, 화면이 숨겨질 때, 세션 종료 시에 묶음으로 이루어진다.

| 표시 | 의미 | 할 일 |
|---|---|---|
| **동기화 완료** | 시트에 저장되고 재조회로 확인됨 | 없음 |
| **동기화 전 N건** | 아직 기기에만 있음 | 인터넷 연결을 유지하고 잠시 기다리거나 **지금 동기화**를 누른다. |
| **다시 연결 필요** | 구글 연결이 만료됨(약 1시간마다 정상) | **다시 연결**을 누른다. 기록은 그대로 보존된다. |
| **오프라인** | 연결이 끊김 | 연결이 돌아오면 자동 전송. 이 기기에만 N건이 있음을 기억한다. |
| **읽기 전용** | 시트에 쓸 수 없음(권한, 충돌, 새 버전 데이터) | §10 문제 해결 참고 |

**기기를 바꾸기 전에는 배지가 "동기화 완료"인지 확인한다.**

### 4.6 문제 신고

- 해설 화면의 **문제 신고**에서 사유(정답 오류 / 해설 오류 / 부자연스러운 일본어 / 난이도 부적절 / 기타)를 고른다.
- 신고한 항목은 **즉시 내 학습 풀에서 제외**된다.
- 설정 > 콘텐츠에서 **신고 목록 내보내기**로 `flags.json`을 만들고, PC에서 `npm run content:triage -- --flags flags.json`으로 다시 검증하고 고친다(수정본은 새 버전의 콘텐츠로 들어간다).

### 4.7 표시 설정 (설정 > 표시)

- 글자 크기 **작게 / 보통 / 크게 / 아주 크게**(내부 S / M / L / XL), 후리가나 **항상 / 학습 때만 / 숨김**, 화면 색 **시스템 / 밝게 / 어둡게**(다크 모드).
- 글자는 자동으로 줄어들지 않는다. 화면에 안 맞는 긴 지문은 **페이지 버튼**으로 나뉜다.

### 4.8 학습 시간 계산

- 타이머를 켜지 않아도 **실제 학습 시간**은 측정된다. 화면이 숨겨지거나 일정 시간 조작이 없으면 측정이 멈춘다.
- 하루 한도는 60분이다. 콘텐츠가 부족한 영역(예: v2.0.0 전의 청해)은 "준비 중으로 제외"되고 다른 영역으로 재배분되며, **60분 미만인 날도 정상**이다.

## 5. 콘텐츠 추가 루틴 (2주마다, PC)

콘텐츠는 한꺼번에 만들지 않고 **초기 분량 + 점진 추가**로 늘린다. 앱의 **런웨이(남은 학습 분량, 일 수)**가 기준이다.

### 5.1 언제 하나

- 앱의 설정 > 콘텐츠 또는 홈에서 **"남은 학습 분량: N일"**을 확인한다.
- **14일 미만이면 홈에 "콘텐츠 추가 필요"** 안내가 뜬다. 권장 주기는 **2주마다 28일분**이다.
- 모바일만 쓰는 기간에도 런웨이가 0이 되지 않도록 PC 작업일을 미리 정해 둔다.

### 5.2 절차

```text
1) 앱: 설정 > 콘텐츠 > 진도 내보내기 → progress.json 저장
   (휴대폰이면 PC로 옮긴다: 메일, 메신저 나에게 보내기, 드라이브 등)

2) PC 터미널(jlpt-app 폴더):
   npm run content:doctor          ← Claude 연동(API/headless) 점검. 처음 1회와 문제가 있을 때
   npm run content:plan -- --progress progress.json --days 28
      → 부족한 영역과 약점 태그를 반영한 생성 계획 확인

3) npm run content:fill -- --days 28 --max-usd 5 --dry-run
      → 예상 비용(API) 또는 예상 호출 수(headless) 확인, 생성은 하지 않음
   npm run content:fill -- --days 28 --max-usd 5
      → 생성 → 자동 검증 → 팩 파일 생성 (packs/ 폴더)
   (headless 방식이면 --max-calls 200 처럼 호출 수 상한을 준다.
    방식을 한 번만 바꿔 보려면 --provider api 또는 --provider headless)

4) 청해가 있는 경우:
   npm run content:audio -- --all-missing
   npm run deploy            ← 외부에 게시되므로 승인 후 실행

5) 앱(PC 브라우저 권장): 설정 > 콘텐츠 > 가져오기 → packs/ 의 파일 선택
   → 검사 리포트 확인 → 가져오기 승인
```

- 가져오기는 **PC 브라우저에서 하는 것을 권장**한다(파일 선택이 쉽다). 내용은 시트에 저장되므로 휴대폰에서도 바로 보인다.
- 처음 몇 번은 반드시 `--dry-run`으로 확인한다. **API 방식**은 `maxUsdPerRun`을, **headless 방식**은 `maxCallsPerRun`(또는 `--max-calls`)을 넘으면 생성이 멈춘다.
- `progress.json`에는 영역별 정확도, 오개념 태그별 오답 수, 미노출 수, 복습 잔량, 런웨이만 들어 있다. 시트 URL, 계정, 토큰, 개별 풀이 기록은 없다.

### 5.3 가져오기 리포트 읽는 법

| 항목 | 의미 |
|---|---|
| 신규 | 시트에 새로 추가됨 |
| 중복 | 이미 있는 내용이라 건너뜀(기존 ID를 표시) |
| 충돌 | 같은 ID인데 내용이 달라 거부됨(`INTEGRITY_CONFLICT`) |
| 거부 | 형식 오류, 해시 불일치, 위험한 문자열 등(사유 표시) |
| 강등 | 검증 증명이 부족해 **미검증(UNVERIFIED)**으로 바뀜 |
| 보류 | 참조하는 항목이 없어 반영하지 않음 |

- 내용이 아주 비슷한(0.85 이상) 항목은 기본으로 건너뛰고 리포트에 "유사 항목"으로 나온다. 정말 넣고 싶으면 그 줄의 **그래도 추가**를 체크한다.
- 시트에 연결되어 있으면 승인 즉시 `_JLPT_CONTENT`에 200행씩 기록한다(요청 한도를 지키려고 약 1초 간격). 중간에 끊겼다면 **같은 파일을 다시 가져오면** 남은 것만 이어서 기록된다. 연결 전에 가져온 콘텐츠는 연결할 때 자동으로 올라간다.

- **미검증 콘텐츠**는 기본적으로 학습에 나오지 않는다. 설정 > 콘텐츠의 **"미검증 콘텐츠 포함 (연습에만 사용)"**을 켜면 **연습에만** 사용된다. 평가 세트에는 검증된 항목만 들어간다.
- 가져온 팩의 "검증됨" 표시는 **서명이 없는 자가 신고 값**이다. 출처가 불분명한 팩은 가져오기 전에 PC에서 `npm run content:verify -- --pack <파일>`로 다시 검증한다.

### 5.4 장기 목표 확인

`npm run content:catalog`는 장기 목표(현재 목표 N3 기준: 어휘 2,000, 문법 200, 독해 40, 청해 100 등) 대비 부족분을 보여 준다. N2/N1은 등급별 목표 파일을 추가하면 같은 방식으로 쓴다. **필수 목표가 아니라 참고용**이다.

### 5.4.1 개별 명령 (수동으로 한 단계씩 실행할 때)

`content:fill`(자동 순환, v1.0.0 작업에서 제공) 대신 단계를 직접 실행할 수 있다. 모든 명령은 저장소 루트에서 `npm run <이름> -- <옵션>` 형태로 쓴다.

| 명령 | 하는 일 |
|---|---|
| `content:doctor` | Claude 연동(API / headless)과 TTS 키를 점검하고, 쓸 수 있는 방식을 알려 준다. |
| `content:gen -- --kind VOCAB --count 20 --dry-run` | 생성 없이 **예상 호출 수**(API 방식이면 예상 비용도)만 출력한다. `--dry-run`을 빼면 초안을 만든다. 옵션: `--level`, `--pool LEARN|DIAG|ASSESS`, `--topic`, `--domain`, `--provider api|headless`, `--max-usd`, `--max-calls` |
| `content:verify -- --run <실행ID>` | 초안을 자동 검증한다(스키마·읽기·블라인드 풀이·오답 점검·품질·중복). 중간에 멈췄다면 같은 명령을 다시 실행하면 **이어서** 진행한다. |
| `content:verify -- --pack <팩 파일>` | 팩의 해시·개수 무결성을 점검한다. |
| `content:pack -- --run <실행ID> --out packs/<이름>.jlptpack.json` | 검증을 통과한 항목만 팩으로 묶는다. |
| `content:ledger -- --from-pack <전체 내보내기 파일>` | 중복 장부(`content/ledger.json`)를 다시 만든다. |
| `content:catalog` | 장기 목표 대비 부족분을 보여 준다. |
| `content:sample -- --n 20` | 사람이 훑어볼 표본을 `content/sample.md`로 만든다(필수 아님). |
| `content:seed` | 앱에 내장되는 시드(진단 28문항 등)를 만든다. 개발자용. |

- 실행 결과는 `content/runs/<실행ID>/`에 쌓인다(`drafts` → `verified` / `rejected` / `unverified` / `duplicates`). 이 폴더는 깃에 올라가지 않는다.
- 생성 모델과 검증 모델이 서로 다른 것으로 **확인되지 않으면** 항목은 `unverified`로 나뉘고 팩에 들어가지 않는다.

### 5.5 Claude 연동 방식 선택 가이드

| 구분 | API 방식 | headless 방식 |
|---|---|---|
| 호출 방법 | Anthropic API (API 키) | `claude -p`를 자식 프로세스로 실행 (Claude Code 로그인) |
| 비용·한도 | 사용량만큼 달러로 과금, `maxUsdPerRun`으로 제어 | 구독 사용량 한도 안에서 사용, `maxCallsPerRun`으로 제어 |
| 속도 | 빠름(동시 호출 가능) | 상대적으로 느림(기본 동시 2개) |
| 준비물 | API 키, 콘솔 사용 한도 | Claude Code 설치·로그인 |
| 추천 상황 | 한 번에 많이 만들 때, 비용을 정확히 알고 싶을 때 | API 키가 없을 때, 소량을 점진 추가할 때 |

- **섞어 쓰기:** `config.local.json`에서 생성은 headless, 검증은 API처럼 역할별로 다르게 지정할 수 있다. 어느 조합이든 **생성 모델과 검증 모델은 서로 달라야** 검증을 통과(`VERIFIED`)할 수 있다.
- **결과 품질 기준은 같다.** 두 방식 모두 같은 프롬프트와 같은 검증 규칙(§4.4 블라인드 풀이 등)을 쓴다. 팩에는 사용한 연동 방식이 기록된다.
- **headless의 주의점:** 호출마다 새 세션으로 실행되고, 저장소와 분리된 빈 폴더에서 도구 없이 텍스트만 주고받는다. 사용량 한도에 걸리면 자동으로 대기 후 재시도하며, 계속 막히면 멈춘다. 같은 명령을 다시 실행하면 이어서 진행한다.
- **모델 확인 한계:** headless에서는 실제 사용된 모델 이름을 알 수 없으면 요청한 별칭만 기록되고, 이 경우 생성·검증 모델이 다른지 확인할 수 없어 `UNVERIFIED`로 처리될 수 있다. 이때는 검증 쪽을 API 방식으로 바꾼다.

## 6. 콘텐츠 내보내기·가져오기 (공유)

### 6.1 내보내기

1. 설정 > 콘텐츠 > **내보내기**에서 유형(가나·어휘·한자·문법·문제·지문·청해)을 고르고 **팩 내보내기**를 누른다. (**미검증 포함**을 켜면 미검증 항목도 담긴다.)
2. 범위를 **전체**로 하거나 **유형별**(가나, 어휘, 한자, 문법, 문제, 지문, 청해)로 고른다. 레벨과 풀 필터를 쓸 수 있다.
3. 기본은 **검증된(VERIFIED) 항목만** 포함한다.
4. `jlpt-pack_<유형>_<날짜>_<번호>.jlptpack.json` 파일이 저장된다.
5. 개인 학습 기록, 설정, 시트 URL, 토큰은 **포함되지 않는다.**

**전체 내보내기**는 PC의 중복 장부를 다시 만들 때도 쓴다: `npm run content:ledger -- --from-pack <전체 내보내기 파일>`. 장부는 중복 생성을 막는다. 새 PC로 옮기거나 `content/` 폴더를 잃었을 때 실행한다.

### 6.2 다른 사람에게 받은 팩 가져오기

1. 가져오기에서 파일을 선택하고 **전체 또는 유형별**로 고른다.
2. 앱이 **쓰기 전에** 형식, 스키마, 해시, 문제 규칙, 안전성, 참조, 중복을 검사하고 리포트를 보여 준다.
3. 내용을 확인한 뒤 승인해야 시트에 반영된다. 중간에 끊겨도 같은 파일을 다시 가져오면 **이어서** 반영된다(중복 없음).

### 6.3 청해 항목을 공유할 때

- 팩에는 **음원 파일이 들어 있지 않고 스크립트만** 들어 있다. 받는 사람이 `content:audio`로 음원을 만들면 되고, 만들기 전에는 `BROWSER_TTS`(브라우저 음성)로 재생되며 **평가에서는 제외**된다.

## 7. 청해 사용법과 한계

- 청해 음원은 **TTS로 생성한 mp3**다. 실제 JLPT 음성과 **억양, 속도, 잡음 환경이 다를 수 있다.** 그래서 청해 준비도 옆에 **"TTS 음원 기반"** 배지가 항상 표시된다.
- 재생 버튼을 누를 때만 음원을 내려받는다(데이터 절약). 평가용 청해는 **기본 1회 재생**, 연습은 횟수 제한이 없다(설정에서 변경 가능).

### 7.1 음원 품질을 개선하는 방법

| 방법 | 설명 |
|---|---|
| 엔진·음성 교체 | 다른 TTS 엔진이나 음성으로 `content:audio`를 다시 실행하면 새 음원이 만들어진다. |
| **사람 녹음으로 교체** | `audio/overrides/<contentId>.mp3`를 넣고 배포하면 해당 문항이 `RECORDED`(녹음본)로 바뀌고 평가에서도 우선한다. |
| 브라우저 음성 | 음원 파일이 없을 때 자동 대체되며 **평가에는 기본 제외**. 설정에서 평가 포함으로 바꿀 수 있지만 품질 편차가 있다. |

설정 > 고급에서 **음원 소스별 구성 비율**(생성 / 녹음 / 브라우저)을 볼 수 있다.

## 8. 준비도와 리포트 읽는 법 (v3.0.0부터)

- 앱은 **합격 확률이나 JLPT 예상 점수를 표시하지 않는다.** JLPT 점수 환산식이 공개되어 있지 않기 때문이다.
- **영역별(언어지식 / 독해 / 청해) 준비도**는 처음 보는 평가 문항에서의 `맞은 수/푼 수`, 소요 시간, 표본 수로 표시된다.
- **`자료 부족`**: 영역별 평가 문항이 20개 미만이면 표시된다. 판단하지 말고 평가 세트를 더 푼다.
- **`상대 취약 영역 주의`**: 다른 영역보다 눈에 띄게 낮을 때 표시되는 **학습 우선순위 경고**다. JLPT 공식 과락 판정이 아니다.
- **JLPT N3**의 합격 기준은 **총점 95/180 이상 + 세 영역 각 19/60 이상**이다(공식). 다른 등급은 기준과 영역 구성이 다르며, 앱은 설정한 목표 등급의 공식 기준에 맞춰 표시한다. 한 영역이라도 기준에 못 미치면 총점이 높아도 불합격이므로 청해와 독해를 비우지 않는다.
- 학습 중 이미 본 문제는 평가에 쓰이지 않는다. 해설을 보고 다시 푼 같은 문제의 정답은 **신규 평가 성과로 세지 않는다**.

## 9. 백업·복원·기기 변경·버전 업

### 9.1 백업

- **정본은 시트**지만 다음 세 가지를 습관으로 둔다.
  1. 월 1회: 설정 > 백업 > **JSON 내보내기** (개인 기록과 설정, 토큰은 포함되지 않음)
  2. 중요한 시점(시험 전 등): 구글 시트 **파일 > 사본 만들기**
  3. 구글 시트의 **버전 기록**(파일 > 버전 기록)으로 이전 상태를 되돌릴 수 있다. 단, 되돌리면 이벤트가 과거 시점으로 돌아가므로 신중하게 사용한다.

### 9.2 새 기기에서 시작

1. 새 기기의 Chrome에서 앱 주소를 연다.
2. 같은 구글 계정으로 연결하고 **같은 시트 URL**을 붙여 넣는다.
3. 앱이 시트에서 설정, 목표, 학습 기록, 콘텐츠를 복원한다. 진단을 새로 시작하지 않는다.

### 9.3 앱 업데이트(버전 업)

- 업데이트는 PC에서 `npm run build` 후 `npm run deploy`로 **같은 주소에 덮어쓴다.** (게시 승인 필요)
- 설정과 학습 기록은 시트에 있으므로 유지된다. 브라우저에 오래된 화면이 남아 있으면 새로고침한다.
- 앱이 "앱 데이터 버전을 확인할 수 없어 쓰기를 중단했습니다"라고 하면, 시트가 **더 새로운 버전의 데이터**를 가진 경우다. 앱을 최신으로 업데이트한다. 시트를 되돌리거나 초기화하지 않는다.

### 9.4 `file://` 로컬 모드의 백업

- `index.html`을 파일로 직접 열면 구글 연결이 되지 않고, 브라우저가 기록을 얼마나 보존하는지 보장되지 않는다. 화면의 **백업 내보내기**를 자주 사용한다.
- 로컬 모드에서 만든 백업은 나중에 HTTPS 앱에서 **가져와 병합**할 수 있다(중복 이벤트는 한 번만 반영).
- 브라우저가 저장소(IndexedDB) 사용을 막으면 홈과 설정에 **"현재 실행에서만 유지됨 — 백업 권장"** 경고가 뜬다. 이때는 탭을 닫으면 기록이 사라질 수 있으므로 바로 **JSON 내보내기**를 한다.
- 가져오기는 파일을 고르면 먼저 **신규 / 중복 / 충돌 / 거부** 건수를 보여 주고, **가져오기 승인**을 눌러야 반영된다. 반영된 기록은 시트로 전송되기 전이므로 "동기화 전"으로 표시된다.

---

### 9.5 N2/N1로 확장할 때 (설계, T18에서 구현)

- 앱은 특정 등급에 묶여 있지 않다. 목표 등급은 설정값(`targetLevel`)이며, 처음에는 N3다.
- N2나 N1을 추가할 때는 새 앱을 만들지 않는다. 같은 저장소(`jlpt-app`)와 같은 시트를 쓴다.
  1. 등급별 목표 파일(`tools/content/targets/N2.json` 등)과 진단·시험 구조를 추가한다.
  2. `npm run content:fill -- --level N2 --days 28`처럼 해당 등급 콘텐츠를 생성·가져오기 한다.
  3. 콘텐츠가 있는 등급만 설정 > 목표에서 **목표 급수**로 선택할 수 있다.
- 목표 등급을 바꿔도 **기존 학습 기록과 N3 콘텐츠는 지워지지 않는다.** 준비도와 리포트는 등급별로 따로 표시된다.

## 10. 문제 해결

| 증상·메시지 | 원인 | 해결 |
|---|---|---|
| "로컬 파일 모드에서는 Google 로그인을 지원하지 않습니다" | `file://`로 열었다. | Pages 주소(`https://...github.io/...`)로 접속한다. |
| 로그인 창이 안 뜸 / "Google 로그인 창을 열 수 없습니다" | 팝업 차단, 연결 문제 | 브라우저 팝업 허용 후 다시 누른다. 보안 설정을 끄지 않는다. |
| 로그인 시 "access blocked / 승인되지 않은 앱" | 테스트 사용자에 본인이 없음 | §1.2의 4번에서 본인 계정을 테스트 사용자에 추가한다. |
| 로그인 후 "origin mismatch" 오류 | OAuth 원본 주소 불일치 | §1.2의 6번 JavaScript 원본이 **경로 없이** 정확히 일치하는지 확인한다(`https://<사용자명>.github.io`). |
| "Google 연결이 만료되었습니다" | 토큰 만료(정상, 약 1시간) | **다시 연결**을 누른다. 기록은 보존된다. |
| "이 계정에서는 필요한 Google Sheets 권한을 사용할 수 없습니다" | 계정 정책(Workspace) 또는 Sheets API 미사용 | 개인 계정으로 연결하고 Cloud 프로젝트에서 Sheets API가 켜져 있는지 확인한다. |
| "이 스프레드시트에 앱 기록을 쓸 수 없습니다" | 보기 권한만 있거나 보호된 탭 | 시트의 편집 권한을 확인하거나 다른 시트를 선택한다. |
| "시트를 찾지 못했거나 현재 계정에서 열 수 없습니다" | URL 오류 또는 다른 계정으로 로그인 | 주소창 URL 전체를 다시 복사하고 같은 계정인지 확인한다. |
| "유효한 Google 스프레드시트 링크를 입력해 주세요" | URL 형식 오류 | `https://docs.google.com/spreadsheets/d/<ID>/...` 형태인지 확인한다. |
| "기존 기록용 탭이 있어 자동 초기화할 수 없습니다" | `_JLPT_` 탭이 있는데 앱 구조와 다름 | 시트를 직접 고치지 않는다. 새 빈 시트를 만들어 연결하거나 백업에서 복원한다. |
| "다른 계정의 학습 기록이 연결되어 있습니다" | 시트에 다른 계정의 기록이 있음 | 본인 시트인지 확인한다. 임의로 병합하지 않는다. |
| "동기화 전 N건"이 줄지 않음 | 오프라인, 429(요청 한도), 읽기 전용 | 연결을 확인하고 **지금 동기화**를 누른다. 한도 지연은 자동 재시도된다. |
| "연결이 끊겼습니다. N건이 기기에만 저장되어 있습니다" | 오프라인 | 연결 후 자동 전송된다. 그동안 브라우저 데이터를 삭제하지 않는다. |
| 홈·설정에 "현재 실행에서만 유지됨 — 백업 권장" | 브라우저가 저장소 쓰기를 막음(시크릿 창, 저장소 차단, 일부 `file://`) | 일반 창에서 HTTPS 주소로 열거나, 지금 **JSON 내보내기**로 백업한다. |
| 읽기 전용으로 전환됨 | 권한, 충돌, 새 스키마 | 안내 문구에 따른다. JSON 백업을 받아 두고 §9.3을 확인한다. |
| 홈에 "콘텐츠 추가 필요" | 런웨이 14일 미만 | §5 절차를 실행한다. |
| 가져온 콘텐츠가 학습에 안 나옴 | `UNVERIFIED` 강등, 신고로 제외, 이미 노출 | 가져오기 리포트를 확인하고 필요하면 "미검증 콘텐츠 포함"을 켠다. |
| 새 음원이 재생되지 않음 | 배포 반영 지연, 캐시 | 몇 분 기다린 뒤 새로고침한다. 그래도 안 되면 `audio/` 파일명(키)과 배포 여부를 확인한다. |
| `content:fill`이 중간에 멈춤 | 비용 한도 도달, 모델 오류 | 보고된 이유를 확인한다. 같은 명령을 다시 실행하면 **이어서** 진행된다. |
| 생성 비용이 예상보다 큼 | 재작성(REVISE) 반복 | `--dry-run`과 `--max-usd`를 낮추고 콘솔 사용 한도를 확인한다. |
| Claude Code가 `BLOCKED(LLM)`을 보고 | API 키도 없고 headless도 쓸 수 없음 | §1.4의 A 또는 B를 준비하고 `npm run content:doctor`로 확인한 뒤 이어서 진행하도록 지시한다. |
| `content:doctor`에서 API 방식 실패(401 등) | API 키 오류·만료·한도 | `.env.local`의 키를 확인하고 콘솔에서 키와 사용 한도를 점검한다. |
| `content:doctor`에서 "claude 명령을 찾을 수 없음" | Claude Code 미설치 또는 경로 문제 | 설치하고 새 터미널을 열어 `claude -v`가 되는지 확인한다. |
| headless 방식에서 로그인 요구 | 로그인 만료 | 터미널에서 `claude`를 실행해 로그인한 뒤 다시 실행한다. |
| headless 방식에서 사용량 한도·속도 제한 | 구독 한도 도달 | 잠시 후 같은 명령을 다시 실행한다(이어서 진행). `--max-calls`를 낮추거나 `--provider api`로 바꾼다. |
| 생성이 자주 "응답 형식 오류"로 재시도됨 | 모델이 JSON 형식을 지키지 않음 | 자동 재시도 2회 후 해당 항목은 재작성 또는 폐기된다. 반복되면 모델·방식을 바꿔 본다. |
| 항목이 `UNVERIFIED`로만 나옴 | 생성·검증 모델이 같거나 확인 불가 | 두 역할의 모델을 다르게 설정하고, headless 모델명이 확인되지 않으면 검증을 API 방식으로 바꾼다. |

해결되지 않으면 **화면 문구, 배지 상태, 사용 기기와 브라우저**를 메모해 Claude Code에 전달한다.

## 11. 보안·비용·개인정보

- **절대 하지 않는 것:** API 키, OAuth 클라이언트 보안 비밀번호, 액세스 토큰을 깃에 올리거나 채팅·메신저에 붙여 넣기.
- 클라이언트 ID는 공개되어도 되는 식별자이지만 `config.local.json`에 둔다.
- **`spreadsheets` 권한은 넓다.** 앱은 입력한 시트 하나만 다루도록 만들지만, 의심되면 구글 계정의 **보안 > 서드 파티 앱 접근** 화면에서 앱 권한을 해제할 수 있다 ⚠. 권한을 해제해도 시트의 데이터는 삭제되지 않는다.
- **Pages 주소는 코드가 공개된 웹 주소**일 수 있다. 개인 데이터는 공개 저장소에 올라가지 않지만, 저장소에 개인 시트 URL을 커밋하지 않는다.
- **비용 관리:** **API 방식**은 Anthropic 콘솔의 사용 한도, `maxUsdPerRun`, `--dry-run`을 함께 쓴다. **headless 방식**은 구독 사용량 한도와 `maxCallsPerRun`, `--dry-run`(예상 호출 수)으로 관리하며, 구독으로 자동화 호출을 해도 되는지는 약관을 확인한다 ⚠. TTS 무료 한도는 T00에서 확인한 값을 `docs/qa/limits.md`에서 본다.
- **공식 문제·음원·교재 문장을 앱이나 팩에 복사하지 않는다.** 앱의 모든 문제는 오리지널이어야 한다.

## 12. 해도 되는 것 / 하면 안 되는 것

| 하면 안 되는 것 | 이유 |
|---|---|
| 시트의 `_JLPT_*` 탭을 직접 편집·삭제·이름 변경 | 해시와 이벤트 무결성이 깨져 읽기 전용으로 전환될 수 있다. 열람만 한다. |
| 같은 시트를 서로 다른 계정으로 번갈아 연결 | 계정 불일치로 쓰기가 중단된다. |
| 동기화 대기가 남은 채 브라우저 데이터 삭제 | 기기에만 있던 기록이 사라진다. |
| 오래된 앱 파일로 되돌리기 | 새 스키마 시트와 호환되지 않는다. |
| `file://`로 연 채 구글 연결을 시도하거나 우회 | 지원되지 않으며 보안상 금지다. |
| 신고한 항목의 `FLAGGED` 상태를 시트에서 직접 수정 | `content:triage`로 새 버전을 만든다. |

## 13. 용어집

| 용어 | 뜻 |
|---|---|
| **런웨이** | 아직 보지 않은 콘텐츠로 며칠을 더 학습할 수 있는지(일). 영역별 중 가장 작은 값 |
| **팩(pack)** | 콘텐츠를 묶은 `*.jlptpack.json` 파일 |
| **VERIFIED / UNVERIFIED** | 자동 검증을 통과한 항목 / 검증 증명이 없어 강등된 항목 |
| **FLAGGED / RETIRED** | 신고되어 제외된 항목 / 폐기된 항목 |
| **LEARN / DIAG / ASSESS** | 학습용 / 진단용 / 평가 전용 문항 풀. 평가 풀은 학습 화면에 나오지 않는다. |
| **블라인드 풀이** | 검증 모델에게 정답을 숨기고 풀게 해 문제를 점검하는 방식 |
| **API 방식 / headless 방식** | 콘텐츠 생성기가 Claude를 호출하는 두 방법. API 키로 직접 호출하는 방식 / `claude -p`로 Claude Code를 비대화형 실행하는 방식 |
| **`content:doctor`** | 사용 가능한 Claude 연동 방식과 TTS 키를 점검하는 명령 |
| **TTS 음원 기반** | 청해 음원이 음성 합성으로 만들어졌음을 알리는 배지 |
| **GENERATED_FILE / RECORDED / BROWSER_TTS** | 합성 음원 파일 / 사람 녹음 / 브라우저 실시간 음성 |
| **정본** | 기준이 되는 원본 데이터. 이 앱에서는 내 구글 시트 |
| **동기화 완료** | 시트에 쓰고 다시 읽어 확인한 상태 |
| **예상일 / 확정일** | 규정상 첫째 일요일로 계산한 날짜 / 공식 공고로 확인한 날짜 |
| **BLOCKED** | 사용자 준비물이나 권한이 없어 진행하지 못하는 상태 |
