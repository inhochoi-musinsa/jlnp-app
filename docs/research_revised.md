## 1. 시험 구조: 시간·문제 유형·척도점수·합격선

### 결론

**[공식 확인 / 신뢰도: 높음]** N3 시험은 **① 문자·어휘 30분, ② 문법·독해 70분, ③ 청해 40분**으로 나뉜다. 단순 합계 시험시간은 **140분**이며, 실제 체류시간에는 안내·교시 간 대기 등이 더해진다. 성적표의 채점 영역은 **언어지식(문자·어휘·문법), 독해, 청해** 각 0~60점이다. **총점 95/180 이상과 세 영역 각각 19/60 이상**을 모두 충족해야 합격한다. 어느 필수 교시라도 결시하면 불합격 처리된다.

| 구분 | 시행 교시 | 시간 | 채점 영역 |
|---|---|---:|---|
| 문자·어휘 | 1교시 | 30분 | 언어지식 점수에 포함 |
| 문법·독해 | 2교시 | 70분 | 문법→언어지식, 독해→독해 점수 |
| 청해 | 3교시 | 40분 | 청해 점수 |

**[공식 확인 / 신뢰도: 높음]** 출제 *유형*은 다음과 같다.

### 척도점수 설명과 제품 제약

- **[공식 확인]** JLPT는 정답 개수의 단순 합계가 아닌 **문항에 대한 응답 패턴을 반영한 척도점수(scaled scores)** 를 사용한다. 공식 안내의 목적은 서로 다른 회차 간 난이도 차이가 평가에 미치는 영향을 줄이는 것이다.
- **[미확인/삭제]** '쉬운 문제를 틀리면 반드시 큰 페널티', '어려운 문제를 찍어 맞히면 점수 효과가 작음', 'JLPT가 2PL/3PL을 사용하며 1.5배 감점을 할 수 있음'은 공식 공개 자료로 입증할 수 없다. 점수변환식·문항 모수는 공개되어 있지 않다.
- **[실무 제안]** 내부 모의시험에서는 `문항 정답률(원점수)`, `문제 유형별 숙련도`, `소요시간`만 명시한다. 공식 점수인 것처럼 0~60으로 정규화하거나 '예상 JLPT 척도점수'를 생산하지 않는다.
- **[공식 확인]** 2025년 12월 시험부터 JLPT 합격자 성적표에 CEFR 수준이 **참고 정보**로 표기된다. N3 합격 후 **95~103점은 A2, 104~180점은 B1**으로 참조되나 말하기·쓰기를 평가했다는 의미는 아니다.

## 2. 출제 범위: 한자·어휘·문법 목록의 지위와 구축 방법

### 결론

**[공식 확인 / 신뢰도: 높음]** 주관기관은 2010년 개정 후 공식 어휘·한자·문법 출제 명세 목록(Test Content Specifications)을 공개하지 않는다. 따라서 'N3 필수 한자 650자 / 어휘 3,750~4,000개 / 문법 130~150개'라는 **공식 또는 준공식 정답 목록은 없다**.

| 항목 | 원본의 추정치 | 검증된 근거 | 수정된 사용 기준 |
|---|---|---|---|
| 한자 | 누적 약 650자 | 구 2·3급 사이 수준이라는 설명은 있으나 신 N3 공식 목록 부재 | **[미확인]** 650을 학습량 *가설*로만 사용; 고유 한자/한자어 분리 |
| 어휘 | 누적 약 3,750~4,000개 | 출판사마다 포함 범위·표제어 기준이 다름. 3A `新完全マスター語彙 N3`은 **약 1,200어**를 수록한다고 명시 | 1,200은 해당 **교재 수록량**이지 N3 총 어휘 수가 아님 |
| 문법 | N3 추가 약 130~150개 | 3A 문법 교재의 실제 구성 확인. 전체 문형 수를 주관기관이 규정하지 않음 | **[미확인]** 문형 묶음/변형형 중복 집계 기준 정의 |

**[정정]** 'JMDict·KANJIDIC2가 2010~2024 실제 기출을 역추적하여 공식 N3 레벨을 붙인 데이터베이스'라는 원본 설명은 부정확하다. **JMdict**는 범용 일본어 어휘 사전이며, **KANJIDIC2**의 JLPT 메타데이터는 구시험 시대의 수준 표기에서 출발했다. 현대 N3 매핑은 별도의 서드파티 목록·자체 검증이 필요하다.

### 앱 커리큘럼 데이터베이스 권장안 **[실무 제안 / 신뢰도: 중간]**

- 최소 3개 계층: `N5/N4 선수 지식`, `N3 목표 표현`, `N2/N1 확장`. 각 계층은 출제 공식 보증이 아니라 **교육용 분류**.
- `vocab_item`에 `surface`, `reading`, `part_of_speech`, `sense_ko`, `sense_ja`, `example`, `audio_source`, `source_id`, `license`, `level_estimate`, `review_status`, `homograph_group` 보관.
- `grammar_item`에 `pattern`, `attachment_rules(接続)`, `meaning_ko`, `contrast_patterns`, `incorrect_examples`, `test_types`, `source_id` 보관.
- `kanji_item`에 한자의 개별 목록을 만들되 독음 암기는 **어휘 단위**로 연계한다. '한자 650자=일본어 650개 읽기'로 보지 않는다.
- 다중 출처가 다르게 분류하면 `JLPT_N3` 단일 플래그보다 `source_labels:[{source,level,edition,confidence}]` 사용.
- 도입 초기에는 고빈도·고활용 **큐레이션된 소규모 세트**로 시작하고, 실제 모의평가에서 노출·오답 빈도를 근거로 확장한다.
- **라이선스:** 사전/교재의 표제어 목록·예문·설명·음원에는 각각 사용조건이 있다. 상업 교재 전체 복제나 공식 기출·음원 일괄 수집은 별도 법적 검토 또는 허락 없이 수행하지 않는다.

## 3. N5/N4 단계 vs N3 직행: '시험'과 '학습' 분리

### 결론

**[공식 확인 / 높음]** JLPT에는 하위 등급 합격이 상위 등급 응시의 선행요건이라는 규정이 없다. **[실무 제안 / 중간]** 최단 *자격 취득*이 목적이면 **N5·N4 내용은 공부하되 시험 응시는 생략하고 N3에 바로 응시**하는 방법이 합리적이다. 다만 일본어 기초가 부족하면 N3 문제만 반복하는 전략보다 N5/N4의 필수 문법·어휘를 순차적으로 학습해야 한다.

| 전략 | 예상 이점 | 주의·비용 |
|---|---|---|
| N5 시험→N4 시험→N3 시험 | 단계별 객관적 인증·시험 경험, 학습 동기 강화 | 3개 시험 응시일 사이 최소 약 **12개월 간격**(정기적인 반년 간격 두 번). 첫 응시 전 준비기간은 별도 |
| N5/N4 내용 학습→N3만 응시 | 대기하는 시험 회차 감소, 목표 시험에 예산 집중 | 기초 학습을 건너뛰면 독해·청해의 기초 결손 위험 |
| 처음부터 N3 기출 문제만 학습 | 이미 N4 정도 실력이 있는 경우 실전 적응에 유리 | 완전 초보자에게는 비추천; 학습 실패·찍기 패턴 고착 위험 |

### 학습시간 근거의 한계

- **[미확인]** 원본의 '비한자권 650~900시간', '중화권 400~500시간', '한국인 250~350시간'은 동일한 연구 설계·표본·시작 숙련도·합격 기준으로 추적되지 않았다. 특히 '시사/파고다 합격자 수기'를 인용하는데 원본 표본과 정량 분석이 없다. **학술적 확정치 또는 한국인 평균치로 사용하지 않는다.**
- **[미확인]** 한국어 화자의 학습시간 **50% 단축** 주장과 직접 연결되는 정량 연구를 확인하지 못했다.
- **[실무 제안]** 250·350·500시간은 사실 통계가 아니라 `계획 시나리오`를 가리키는 임의 가정으로만 사용할 수 있다. 실제 목표는 **초기 진단, 최근 2~3회의 시간제한 모의평가, 청해 이해도**에 따라 재설정한다.

### 실제 학습자 사례(개인 보고, 일반화 금지)

- **N3 직행 사례:** 2025년 1월 Reddit 게시자는 일본어 지식 없이 시작해 일본 거주 및 직장생활을 병행하면서 **N5/N4 미응시 → N3 응시**, 첫 시험에서 **93/180(불합격)**, 다음 회차에 **112/180(합격)**이었다고 서술했다. 거주지에서의 일상 노출과 자기보고 편향이 있어 **한국에서 하루 1시간만 공부했을 때의 성과 근거는 아님**. [사례 원문](https://www.reddit.com/r/jlpt/comments/1ie8fpd) — **[개인 사례 / 신뢰도: 낮음]**.
- **단계 학습 사례:** 2025년 8월 Reddit 게시자는 성인 직장인으로서 약 **7개월 200시간 학습 후 N4 합격**을 보고하고 N3 학습시간을 질문했다. **N3 실제 합격 소요시간 데이터는 없는 글**이므로 N3의 250~350시간을 뒷받침하는 근거로 사용할 수 없다. [사례 원문](https://www.reddit.com/r/jlpt/comments/1n4siy2/how_many_hours_between_n4_and_n3_as_a_working/) — **[개인 사례 / 신뢰도: 낮음]**.
- **원본의 '사례 A/B'**는 개인 식별 가능한 출처·날짜·성과가 없어 **실제 검증된 사례가 아니라 서술형 가상 시나리오**로 취급하고 삭제했다.

### 학습경로 전환 조건(제안)

1. **진단(15~30분 × 2~3세트)**: 가나 인지, N5/N4 조사·활용, 문장 해석, N3 유형별 단문·청해. 진단은 점수보다 *오답 이유*까지 기록.
2. **기초 보충 경로**: 가나 자동 인지와 N5/N4 문장 이해가 불안정하면 기초를 먼저 편성. 완료 기준은 '몇 주 경과'가 아니라 별도 반복 문제에서 안정적 재현.
3. **N3 집중 경로**: 초급 문장을 무리 없이 읽고 청해 핵심을 포착하면 N3 어휘·문법·독해·청해를 동시 진행.
4. **시험 응시**: 공식 회차까지 남은 기간·전 영역 균형·시간제한 검증 결과로 응시 여부를 판단한다.

**2026-10-15 기준 시간 예산:** 2027-07-04까지 **262일 × 1시간 = 최대 262시간**, 2027-12-05까지 **416시간**(매일 실천 시, 쉬는 날 미반영). 2027년 7월을 목표로 할 경우 원본의 '10개월 300시간' 커리큘럼을 그대로 적용할 수 없다. 목표일이 다르면 앱은 남은 학습 가능 일수를 다시 계산해야 한다.

## 4. 영역별 학습법: 연구 근거와 실제 운영 설정 분리

### 4.1 가나: '외웠다'보다 '즉시 읽는다'

**결론 [실무 제안 / 신뢰도: 중간]:** 히라가나·가타카나를 문자 인식 → 소리 대응 → 단어 속 즉시 인식의 3단계로 훈련한다. 처음 1~2주간 가나에 집중하되 이후에도 실제 어휘로 자동화를 점검한다. 원본의 '히라가나 2~3일, 가타카나 4~7일'은 개인차가 큰 **경험적 예시**이며 검증된 표준 학습시간은 **미확인**.

- 유사 문자(シ/ツ, ソ/ン), 장음(ー), 촉음(っ), 요음(ゃ/ゅ/ょ), 탁음·반탁음에 대한 **혼동쌍 퀴즈**.
- 쓰기 능력보다 **읽기·청취 반응시간**을 우선 측정하되, 쓰기가 기억에 도움이 되는 학습자는 선택적으로 사용.
- 성공 기준 예시: 가나 인지 오류가 줄고, 시간제한 속에서도 어휘를 한 글자씩 해독하지 않음. *정해진 3초 기준 등은 공식 요구사항이 아님.*

### 4.2 어휘·한자: 간격 반복 + 능동적 인출

**결론 [연구 근거 / 높음]:** 분산 반복(distributed practice)과 연습 시험(practice testing)은 다양한 학습 과제에서 장기 보존에 도움이 된다는 강한 근거가 있다. 그러나 특정 JLPT 앱에서 '300% 향상'하는 식의 고정 효과 크기는 검증되지 않았다.

**초기 운영 설정 [실무 제안 / 중간, 검증 필요]**

| 항목 | 시작값 | 동적 조정 원칙 |
|---|---|---|
| 신규 어휘 | 초보 5~10개/일, 기초자 10~15개/일 | 당일 복습 부담 및 7일 보유율에 따라 증감. 무조건 20개 강제 금지 |
| SRS+복습 시간 | 15~20분/일 | 시간 초과 시 신규 카드 중단; 기존 예정 복습 우선 |
| 복습 수 | '50~80개' 고정하지 않음 | SRS가 계산한 *due* 건수와 실제 카드당 시간으로 제어 |
| 기억 유지 목표 | 약 0.85~0.90부터 시험해 볼 수 있음 | FSRS 사용 시 초기 기본값 0.90 참고. 높을수록 복습 부담 증가 |
| 카드 단위 | 단어+읽기+예문+음성 | 한자의 음독/훈독을 무맥락 목록으로 분리 암기하지 않음 |

- Anki의 FSRS는 장기 기억 확률을 모델링하는 스케줄러지만, **FSRS 우위가 곧 JLPT 합격 가능성 증가의 직접 증명은 아니다**.
- 앱에서 새로 FSRS를 구현한다면 공식 FSRS 구현·테스트 결과를 참조하고, 초기 데이터가 부족할 때는 단순 간격 반복으로 시작 가능. '망각 직전'을 완벽히 맞춘다는 표현은 피한다.

**근거 URL:** https://www.psychologicalscience.org/publications/journals/pspi/learning-techniques.html · https://journals.sagepub.com/doi/10.1177/2372732215624708 · https://docs.ankiweb.net/deck-options

### 4.3 문법: 문형 의미·접속·변별·사용을 함께

**결론 [실무 제안 / 중간]:** `문형의 의미와 접속 규칙 → 대조 예문 → 문장 구성 → 문맥 선택지 판별 → 간격 재시험` 순서를 권장한다. 원본의 **이해 30% 대 문제 풀이 70%**는 연구로 입증된 최적 비율이 아니므로 **초기 운영 가설**로만 둔다.

- 설명만 반복하는 방식보다 **인출 문제 + 오답 피드백 + 일정 간격 후 재확인**을 우선.
- 혼동군 예시: `〜ように/〜ために`, `〜そうだ/〜らしい`, `〜ことにする/〜ことになる`, 조사/수수동사/자동사·타동사.
- 맞혔더라도 정답 근거를 설명하지 못하면 '불확실 정답'으로 추적.
- 문법 문항만 많이 맞혀도 독해와 청해의 과락을 해결하지 못함을 명시.

**근거 URL:** https://www.psychologicalscience.org/publications/journals/pspi/learning-techniques.html · https://www.3anet.co.jp/np/books/3604/

### 4.4 독해: 정확도 → 시간제한 → 정보 선택

**결론 [실무 제안 / 중간]:** 초기에 문장 단위 의미 파악과 연결어·지시어 해석을 익히고, 이후 단문·중문·장문·정보검색별 **정확도와 문항당 소요시간**을 함께 기록한다. 원본의 '분당 150~200자'는 표준 목표 근거가 **미확인**이며, '질문 먼저 읽고 키워드 스캔'만 수행하면 함정 선택지에 취약할 수 있다.

- **원문에 근거한 선택**: 정답 근거 문장과 오답 선택지를 연결해 설명.
- **시간 배분 실험**: 70분 공동 교시에서 문법을 약 20~25분, 독해를 45~50분에 풀어 보는 *출발안* 사용. 개인 정확도에 따라 이동. 공식 시간 배정이 아님.
- 중·장문에서 대명사·역접·인과·필자 태도의 흐름을 추적; 정보검색형은 조건표와 예외사항을 확인.
- 결과 기록: 지문 길이, 문제 유형, 정답 여부, 체류시간, 오답 원인(`어휘 부족/논리/선택지 혼동/시간 부족`).

**근거 URL:** https://www.jlpt.jp/e/guideline/testsections.html · https://www.jlpt.jp/e/about/levelsummary.html

### 4.5 청해: 실제 음원 이해를 중심으로

**결론 [실무 제안 / 중간]:** 청해 훈련에는 **실전형 문제, 반복 청취 후 피드백, 스크립트 확인, 선택적 섀도잉/딕테이션**을 조합한다. 원본의 '섀도잉 효과 최상' 및 '매일 10~15분이 최적'은 수치 근거 **미확인**.

| 방식 | 적합한 사용 시점 | 주요 한계 |
|---|---|---|
| 실전형 청해 문항(실제 듣기→응답) | 매주, 특히 모의고사 접근 단계 | 원어민 음원·저작권 확보 필요 |
| 듣기→스크립트 확인→다시 듣기 | 일반 학습의 기본 루프 | 스크립트에만 의존하면 청각 인지가 개선되지 않을 수 있음 |
| 짧은 구간 섀도잉 | 소리 연쇄·박자·문장 단위 처리 보조 | '발화 성공=내용 이해'가 아님; 녹음·비교가 유용 |
| 선택적 딕테이션 | 장단음·조사·부정형 등 반복 오류 진단 | 전량 받아쓰기는 시간 대비 비용 큼 |

- 청해를 후반기에 몰아넣지 않는다. 초기부터 **매일 짧은 듣기 노출**을 확보한다.
- 음성은 원어민 검수 오디오를 최우선으로 사용. TTS 생성 음성만으로 실전 청해를 검증해서는 안 됨.
- 섀도잉·딕테이션의 JLPT N3 한국어 화자 대상 비교 효과 크기는 **미확인**. 앱 자체 A/B 또는 사용자 내 교차 실험으로 평가 가능.

**근거 URL:** https://www.jlpt.jp/e/samples/sampleindex.html · https://www.jlpt.jp/e/about/levelsummary.html

## 5. 하루 60분 기준 커리큘럼: 고정 10개월 대신 적응형

### 기본 시간표 **[실무 제안 / 신뢰도: 중간]**

| 학습 단계 | 어휘·한자/SRS | 문법 | 독해 | 청해 | 합계 |
|---|---:|---:|---:|---:|---:|
| 완전 초보(가나 보충) | 15분 | 20분 | 5분* | 10분 | 50분 + 가나 10분 |
| 기초~N3 본학습 | 20분 | 15분 | 15분 | 10분 | 60분 |
| 청해 약점 보강일 | 15분 | 10분 | 10분 | 25분 | 60분 |
| 독해 약점 보강일 | 15분 | 10분 | 25분 | 10분 | 60분 |
| 시험 전 실전일 | 10분 | 문법·독해 시간제한 세트 35분 | 위 통합 | 청해 세트 15분 | 60분 |

*초보 단계의 독해 5분은 가나와 기초 문장의 의미 인지용이다. 총량 60분을 넘기지 않는다.*

### 목표일 역산 및 전환 규칙

1. **온보딩**: 현재 가나 숙련도, 기존 학습력, 주별 실제 공부 가능 일수, 목표 회차, 약한 영역 수집.
2. **매 7일**: 실제 학습 시간, 신규·복습 카드 평균 소요시간, 영역별 정답률, 청해 이해도, 시간 초과 여부 계산.
3. **매 28일**: 공개 공식 문제 유형을 참고한 신규 제작 문항으로 **보유하지 않은 문항 세트**를 시간제한 진단. 학습에 쓴 문항을 그대로 모의고사에 재사용하지 않는다.
4. **3개 영역 모두 개선**되도록 다음 주 예산 조정. 정답률이 낮고 소요시간이 긴 영역을 우선하되 청해나 독해를 0분으로 만들지 않는다.
5. **최종 4~8주**: 남은 지식 결손을 복습하면서 시간제한 실전 세트·시험 운영 연습 강화. '마지막 3개월은 오직 기출 풀이'처럼 배타적 전환을 하지 않는다.

**전시간 실전의 물리적 제약:** 실제 시험은 교시 합계 140분으로 1일 60분 예산을 초과한다. 평소에는 30/70/40분 **교시별 분할 시뮬레이션**을 수행한다. 시험 전 1~2회 전시간 연속 모의고사는 별도 예외 시간을 확보할 수 있을 때만 진행하며, 60분 제약이 절대적이면 실시하지 못했다는 사실을 준비도 평가에 반영한다.

**원본 '10개월=300시간'의 수정:** 30일×10개월×60분이라는 단순 예산 산식으로는 성취 보장이 불가능하다. '매일 1시간, 300일'은 **상한 학습 가능 시간 300시간**을 뜻할 뿐 합격의 필요충분조건이 아니다.

**출처/신뢰도:** 시간표·전환 규칙은 **실무 제안(중간)**; 시험 시간은 **공식 확인(높음)**: https://www.jlpt.jp/e/guideline/testsections.html

## 9. 로컬 SPA 구현 타당성: Google OAuth·Sheets·TTS·데이터 무결성

### 9.1 localhost 기반 Google API 인증/인가

**결론 [공식 개발문서 확인 / 신뢰도: 높음]:** `http://localhost:<port>`에서 실행되는 **브라우저 SPA**는 Google Cloud의 **Web OAuth 클라이언트** 등록과 승인된 JavaScript origin 설정 후 Google Identity Services(GIS) 토큰 모델로 Sheets API를 호출할 수 있다. **`file://`로 여는 HTML 파일과는 구분**해야 한다. `localhost` 실행이 가능하다는 뜻이지 인터넷이 완전히 끊긴 상태에서 OAuth·Sheets 동기화가 된다는 뜻은 아니다.

**인증(authentication)** 과 **시트 접근 동의(authorization)** 는 별개다. 학습 기록이 로컬에만 있다면 Google 로그인은 필수가 아니다. Google API 권한 요청은 사용자가 '시트 연결/백업'을 누르는 시점에만 수행하는 것이 적절하다.

| 사용자 목적 | OAuth scope | 공식 분류 및 범위 | 권장 |
|---|---|---|---|
| 앱이 사용자가 선택해 연결한 **개별 파일**만 읽고 쓰기 | `https://www.googleapis.com/auth/drive.file` | **비민감(Non-sensitive)**, 앱과 함께 사용하도록 승인된 파일별 권한; Sheets API 지원 | **우선 권장, Picker와 조합** |
| 임의의 사용자가 지정한 시트들 **읽기 전용** | `https://www.googleapis.com/auth/spreadsheets.readonly` | **민감(Sensitive)**, 접근 가능한 모든 Google Sheets 열람 권한 | 링크 직접 입력 UX가 필수일 때 대안 |
| 사용자가 접근 가능한 시트들 **읽고 쓰기** | `https://www.googleapis.com/auth/spreadsheets` | **민감(Sensitive)**, 접근 가능한 모든 Google Sheets 파일의 편집·생성 등 광범위 권한 | 최소 권한에 부합하는 대안이 없을 때만 |

**중요 제약:** 사용자가 시트 URL을 입력했다는 사실만으로 `drive.file`의 해당 파일 권한이 자동 부여되지는 않는다. **Picker 또는 Google이 지원하는 파일 열기/앱 연계 방식으로 해당 파일을 승인**해야 한다. 링크 입력만으로 자유로운 타인 시트 접근은 되지 않으며, 계정이 실제로 그 파일에 접근할 권한도 있어야 한다.

**권장 흐름 [실무 제안]**

1. localhost 개발 서버 시작(`http://localhost:5173` 등) → Cloud 프로젝트에서 **Sheets API 및 필요 시 Drive/Picker API 활성화**, OAuth 동의 화면 구성, 허가할 테스트 사용자 지정, Web 클라이언트 ID 발급.
2. 실제 개발 origin(프로토콜·호스트·포트 포함)을 **Authorized JavaScript origins**에 등록. 프로덕션 배포 시 HTTPS origin을 별도 등록.
3. '스프레드시트 연결' 선택 → `google.accounts.oauth2.initTokenClient(...)` 준비 → **사용자 클릭 이벤트에서** `requestAccessToken()` 호출.
4. 최소 권한 경로: `drive.file` 토큰 + Google Picker를 사용해 해당 시트를 선택·승인 → Sheets API로 메타데이터·값 조회 및 저장.
5. 읽기 전용 또는 광범위 접근이 꼭 필요한 경로: 범위·민감도·Google 앱 검증 요건에 대한 설명과 별도 동의를 제공.
6. 액세스 토큰은 **브라우저 메모리에만** 두고 만료 시 사용자 재동의/재발급 흐름을 제공. SPA 클라이언트에 `client_secret`/장기 refresh token을 저장하지 않음. Google 계정의 조직 정책으로 접근이 제한될 수 있음.

**구현 시 주의:** Google GIS 토큰 모델에는 사용자 제스처와 팝업 UX가 필요하며, 만료된 access token을 백그라운드에서 항상 자동 갱신할 수 있다고 가정하면 안 된다. 공개 앱으로 확대하면 Google OAuth 앱 검증 등이 필요할 수 있다.

- localhost JavaScript origin: https://developers.google.com/identity/oauth2/web/guides/get-google-api-clientid
- GIS 토큰 모델: https://developers.google.com/identity/oauth2/web/guides/use-token-model
- Google Sheets OAuth scope별 분류: https://developers.google.com/workspace/sheets/api/scopes
- Drive `drive.file` + Google Picker: https://developers.google.com/workspace/drive/api/guides/api-specific-auth
- Web Picker 통합: https://developers.google.com/workspace/drive/picker/guides/web-picker

### 9.2 스프레드시트 링크를 입력받는 경우

**결론 [공식 API 확인 / 신뢰도: 높음]:** 링크에서 `spreadsheetId`를 추출하고 `spreadsheets.get`으로 **시트 제목·sheetId(gid)** 메타데이터를 조회한 뒤, `spreadsheets.values.get`으로 값 범위를 가져오는 방식이 가능하다. 단, 실제 액세스에는 위에서 설명한 *적절한 OAuth 권한*이 먼저 필요하다.

예시:

```js
function parseSpreadsheetLink(input) {
  const url = new URL(input);
  if (url.hostname !== 'docs.google.com') throw new Error('Google Sheets URL만 지원');
  const match = url.pathname.match(/^\/spreadsheets\/d\/([A-Za-z0-9_-]+)(?:\/|$)/);
  if (!match) throw new Error('유효한 시트 링크가 아님');
  const gid = new URLSearchParams(url.hash.replace(/^#/, '')).get('gid');
  return { spreadsheetId: match[1], sheetId: gid === null ? null : Number(gid) };
}

async function getSheetValues(spreadsheetId, sheetTitle, token) {
  // sheetTitle은 spreadsheet 메타데이터에서 조회한 실제 제목을 사용.
  // 작은따옴표/특수문자 등 A1 notation escaping을 별도 적용할 것.
  const safeTitle = `'${sheetTitle.replace(/'/g, "''")}'`;
  const range = `${safeTitle}!A:E`;
  const endpoint = `https://sheets.googleapis.com/v4/spreadsheets/${encodeURIComponent(spreadsheetId)}`
    + `/values/${encodeURIComponent(range)}`;
  const resp = await fetch(endpoint, {
    headers: { Authorization: `Bearer ${token}` }
  });
  if (!resp.ok) throw new Error(`Sheets API 호출 실패 (${resp.status})`);
  return resp.json();
}
```

- **`gid`는 스프레드시트 전체 ID가 아니라 개별 탭의 식별자(sheetId)** 이며, Sheets Values API는 셀 조회 시 대체로 탭 **제목(A1 표기)** 을 사용한다. 먼저 메타데이터에서 `sheetId↔title`을 매핑할 필요가 있다.
- URL을 사용자 입력으로 신뢰하지 말고 도메인·경로·ID를 검증한다. Sheet 이름의 특수문자 처리, 헤더 스키마 검증, 행 제한·페이징, 사용자 데이터 유효성 검사를 구현한다.
- 원본의 '공개 시트면 `/gviz/tq?tqx=out:csv`를 무인증 `fetch`할 수 있다'는 방법은 공개 상태·게시 방식·CORS·권한에 따라 실패할 수 있으며 **보편적이고 지원이 보장된 읽기 API가 아니다**. 대안은 **사용자가 직접 CSV 파일 업로드 또는 복사·붙여넣기**, 또는 정식 Sheets API 연결이다.
- 쓰기는 `values.update`/`values.batchUpdate` 등에서 요청 범위와 시트 ID를 명시. 동시 수정 시 **덮어쓰기 충돌 탐지**(로컬 revision/lastSyncedAt, remote stamp)와 사용자 확인을 추가한다.

**공식 URL:** https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/get · https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/get

### 9.3 일본어 음성 합성(Web Speech API)

**결론 [웹 표준 확인 / 신뢰도: 높음]:** Web Speech API의 `speechSynthesis`, `SpeechSynthesisUtterance`, `lang='ja-JP'`, `getVoices()`, `voiceschanged` 사용은 가능하다. **보이스 존재 여부·음질·로컬/원격 여부·발음·시작 지연은 OS·브라우저·설치 음성에 따라 달라지므로 특정 조합을 '최상/0.2~0.5초' 등으로 확정할 근거가 없다.**

- 원본의 '히라가나만 넣으면 발음 오류 99% 방지'는 **[미확인/삭제]**. 한자 오독을 줄일 수 있는 경우가 있지만 전체 문장을 가나화하면 **조사의 は/へ 발음, 단어 경계, 의미에 따른 억양** 등에서 부자연스러운 발음이 발생할 수 있다.
- **권장 파이프라인:** `텍스트 원문 + 검증된 reading + voice profile + 실제 검수 오디오(audioUrl)`을 데이터에 보관하고, **실전 청해/발음학습은 검수된 오디오 우선**, TTS는 예문 반복·접근성·프로토타입 음성용 fallback.
- 음성 준비 시 `speechSynthesis.getVoices().filter(v => v.lang.startsWith('ja'))`로 지원 보이스를 확인; 없으면 음성 학습 대체 경로 제시. `voiceschanged`, `onerror`, `onend`를 다루고 중복 재생·취소·일시중지 테스트.
- 음성 학습 품질 측정: ① 한자 동형다의/다독 ② 장음·촉음 ③ 조사 ④ 숫자·날짜 ⑤ 문장 연결 ⑥ 음성 시작 지연 ⑦ 오프라인 가용성. 실제 타깃 플랫폼에서 QA해야 함.

**공식 URL:** https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/getVoices · https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisUtterance/lang · https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisErrorEvent/error

### 9.4 로컬 퍼스트 저장·보안·복구 **[추가 제안 / 중간]**

- **기본 저장소:** IndexedDB에 사용자 학습 기록·카드 스케줄·문항 풀이를 저장. Google Sheets는 *선택적 가져오기/내보내기·백업*으로 활용; Sheets를 고빈도 카드 이벤트의 실시간 DB로 쓰지 않음.
- **데이터 스키마 버전:** `schemaVersion`, `datasetVersion`, `eventId`, `deviceId`, `occurredAt`, `source`를 이벤트에 기록. N2/N1 확장 시 카드·문항·능력지표를 재사용.
- **오프라인 동작:** 앱 번들과 로컬 카드·이미지 등은 가능하면 오프라인 캐시. OAuth 동의·Sheets 동기화는 네트워크 필요. TTS 오프라인 지원도 구현환경에 따라 달라짐.
- **백업 복원 테스트:** 인증 거부·토큰 만료·시트 삭제/읽기 전용 전환·가져온 CSV 인코딩·중복 sync·다중 탭 충돌·구 버전 복원.
- **데이터 안전:** OAuth 액세스 토큰의 localStorage 보관 회피, 출처가 불분명한 HTML/스크립트 카드 삽입 차단, 스프레드시트 및 CSV 수식 주입 주의, 개인정보 최소 수집.
